# Release v0.3.1 — startup fix + harness corrections (patch)

Patch release: fixes a startup crash that made the window blank, plus four
correctness/security defects in the v0.3.0 harness. No new features.

## What changed in the UI

- Window no longer opens blank after an update. A TDZ init-order bug in the
  store (`Cannot access 'knowledgeBlockRef' before initialization`) threw
  during first render; the app now renders and boots normally.
- Permission dialog "Always" now persists for MCP tools. The rule it saved
  previously refused to store, so "Always" did nothing and re-asked on every
  call.
- MCP tools appear without restarting the app. A tool whose server had not
  connected yet used to be "unknown"; the catalog now refreshes on a miss.
- MCP server with an empty allow-list now exposes no tools. Previously an
  empty allow-list was treated as "allow all", the opposite of intent.
- New toast when images cannot reach a vision model:
  "Couldn't hand images to the vision model — sending text only."
- `@skill` mentions no longer fire inside longer words (`@git-helper_now`).

## Fixes

- **Startup crash (P0).** Refs read by the `contextInfo` memo were declared
  below it; hoisted them. Regression test renders `AppProvider` without a
  browser (`src/lib/store.test.ts`).
- **Keys never cross into JS (#7).** `base_url` removed from the command
  wire entirely; the backend derives it from `connections.base_url` by
  `connection_id`. `#[serde(skip)]` + a serde test guard the upload path.
- **Vision routing (#8).** The decision moved into `streamTurn`, so
  regenerate/retry/continue/edit-resubmit route identically to send.
- **Skills (#9).** Mention regex needs a token boundary; skill content and
  file names strip boundary tags; frontmatter-only files no longer leak
  `---` as their description.
- **MCP (#11).** Scoped approval resources, catalog refresh on miss, empty
  allow-list means none.
- TipTap `onCreate` focus is guarded against a destroyed editor.
