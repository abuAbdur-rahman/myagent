# Release v0.10.1 - Research loop fixes and a cleaner web fetch

Status: release candidate on 2026-11-07. Follows v0.10.0. No migration.

## What changes

- A research turn keeps up to 64 KiB of tool output instead of only the newest
  result. Older results keep a byte count and a 300-character digest, so the
  assistant can see what it already read and stop re-fetching the same page.
- Repeated tool calls are counted across the whole turn. Cache-busting URL
  parameters and search wording are normalized before counting; after three
  repeats the assistant asks Keep going / Stop here once, and another repeat
  ends the turn.
- `web_fetch` returns up to 16,000 characters by default. HTML conversion now
  drops `script`, `style`, `noscript`, `head`, `title`, `meta` and `link` before
  converting, so a documentation page no longer returns a JavaScript banner in
  place of its content.
- The system prompt includes the local date and time and a two-search /
  two-fetch budget for a factual question. `get_time` is cached for the turn,
  and identical normalized web fetches and searches are served from a per-turn
  cache.
- A capped turn is visible: the activity pill shows step X/Y and elapsed time,
  the step-limit banner includes the tool count, and Continue carries a digest
  of completed and failed calls.
- A turn has a 5-minute budget, or 20 minutes after a sandbox, PowerShell or MCP
  tool has run. The final no-tools answer is requested before the budget ends
  and its text is kept, including for subagents.

## Verification

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`,
  `npx tsc --noEmit`, `npm test`, `npm run build`, `fallow dead-code`.
- New tests cover the byte-budget pruning and digest, normalized repeat keys,
  time-budget fallback, script/style stripping, the turn clock in the prompt,
  elapsed formatting, and the Continue digest.
- One OCR pass on the fix commit; both valid findings (newest unique digest,
  failures kept out of the done list) are fixed and covered by tests.

## Not in this release

- True parallel tool execution. Independent calls still run serially; the
  research loop no longer needs it for a simple factual question.
- Persisted per-step trace data or a prompt snapshot. Step and elapsed time are
  live UI only; token usage is still the last step's usage.
- Thin-shell/wrong-page detection, `.md` alternate probing, and passage-window
  extraction in `web_fetch`. The 16k default and the script strip fix the
  reported pricing page; the generic web-fetch hardening is next.
