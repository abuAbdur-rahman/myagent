# Release v0.8.1 - Skills system and sandbox toolchain

Status: release candidate on 2026-10-31. Follows v0.8.0. No migration.

Upgrade from 0.8.0: the installer replaces the app in place and keeps the
database, provider keys, chats, projects and settings. If the sandbox was
enabled, its stored image predates the toolchain, so Settings > Sandbox shows
"out of date" and Rebuild builds the new image once; `sandbox_run` refuses the
old image until then instead of silently running without the toolchain. User
skills written for 0.8.0 still load through the old `name`/`description`
frontmatter.

0.8.1 builds the harness the document skills will use: a skill format with
requirements and an enable switch, a sandbox self-test, and a sandbox image that
already contains the PDF, OCR, Office and deck tooling. It does not ship
`pdf-workbench` or `deck-builder`; those come next against this contract.

## What changes

### Skills

- `SKILL.md` gains our frontmatter: `id`, `title`, `version`, `triggers`,
  `requires_tools`, `requires_imports`, `network`, `writes` and `summary`.
  Existing `name`/`description` files keep loading.
- A user skill shadows a bundled one only when their directory names match:
  the folder name is the skill ID, and the frontmatter `id` does not override
  it. Skills are discovered under the app data folder first, then the bundled
  resources.
- Disabled skills are stored in `<app data>/skills.json`. A disabled skill
  disappears from the model's skill index, the `skill` tool refuses it, and
  `@mention` cannot load it.
- New commands: `skills_list`, `skills_read`, `skills_set_enabled`,
  `skills_doctor`.
- Settings > Skills shows title, version, source and required tools. Each skill
  has an enable switch, Run self-test and Open folder.

### Self-test

- The check runs in the sandbox, not on the host, and returns
  `{ok, missing[], failed_tests[], versions{}, detail}`, where `detail` keeps
  the golden-test log tail.
- `requires_tools` is checked with `command -v` and the first version line is
  captured. Python and Node imports are checked in the same image.
- A skill that ships `tests/run.sh` gets a 120-second golden run from a
  writable scratch folder, with `SKILL_DIR` pointing at the read-only skill
  folder and `OUTPUTS` at the scratch `outputs/`. A failure returns the last 20
  log lines in the result.
- Without a working sandbox, or while the stored image predates the current
  toolchain, `skills_doctor` can return an error instead of a result; the host
  is never probed.
- Skill folders are mounted read-only at `/opt/skills` and `/opt/skills-user`
  for every sandbox command.

### Sandbox toolchain

- New `core`, `office` (default) and `full` profiles. Core adds poppler, qpdf,
  tesseract, ocrmypdf, fonts and the Python venv; Office adds LibreOffice and
  emoji fonts; Full adds CJK fonts and more OCR languages.
- Python packages install from `src-tauri/resources/sandbox/requirements.txt`
  with `--require-hashes` into `/opt/venv`.
- Node 20.20.2 is downloaded from nodejs.org and checked against a pinned
  SHA-256 before use, so the Debian image's older Node cannot be selected.
  Packages install from the committed `package.json` + `package-lock.json` with
  `npm ci` into `/opt/node-tools`, and `NODE_PATH` is set.
- `lo-convert` wraps headless LibreOffice: private profile per job,
  `--norestore`, `flock` so only one conversion runs at a time, and a 60-second
  timeout that kills on expiry.
- The image tag includes the profile, the apt package list and a hash of the
  toolchain files, so repair rebuilds when any of them changed.
- `sandbox_run` refuses `pip install`, `python -m pip install`, `npm install`,
  `npm ci`, `pnpm add`, `yarn add` and `apt`/`apt-get` unless Allow installs is
  on in Settings > Sandbox. That switch is app-wide and stored in
  `sandbox.json`, not per project.

## Not in this release

- `pdf-workbench` and `deck-builder` themselves.
- Separate apt version pinning: apt packages follow the pinned Debian base at
  build time, while Python and Node are pinned by hash.
- A provisioning log dialog and a free-space guard; enabling still shows the
  existing build spinner, and Docker reports its own disk errors.
- License entries for the new components.
- The install guard reads the command string, including `sh -c` and `eval`
  payloads. A script file that runs an installer itself is not inspected; the
  container's missing network is the backstop there.

## Verification

- `npx tsc --noEmit`, `npm test`, `npm run build`.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test --lib`.
- Unit tests cover the frontmatter schema, the doctor script's shell-safety,
  profile package sets, image tags and the install guard.
- The Office image builds locally (2.12 GB), and the ignored
  `toolchain_image_passes_skill_doctor` test builds it and runs the real
  self-test script against a fixture skill: Python imports, Node packages,
  qpdf, soffice, `lo-convert` and a golden test all pass.
- Upgrade smoke on Windows 11: the NSIS installer ran over 0.8.0 with exit 0,
  the uninstall entry and exe report 0.8.1, `myagent.db` is byte-identical,
  the app starts and existing chats load, Settings lists Skills and the
  Sandbox page offers the Core/Office/Full profiles and a rebuild.
