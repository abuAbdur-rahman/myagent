# Release v0.3.2 — design system pass, MCP migrations, issue fixes (minor)

Minor release: the design system becomes binding (and gains the Changelog page),
MCP storage gains an additive migration path, and the three open review issues
are closed out. No breaking change for existing installs.

## Scope

| # | Area | Tracked as |
|---|---|---|
| 1 | Design system pass (settings pages, Changelog page) | `G8` |
| 2 | MCP schema migration + MCP page | `J12` |
| 3 | Issue fixes | #10, #13, #15 |
| 4 | Tool output controls (code-mode Phase 0) | `D19` |

## Design changes

`DESIGN.md` is now the system of record and this release brings the settings
surface up to it.

- **Changelog page (`G8`).** New settings section between Shortcuts and About:
  an installed-version card with **Check for updates**, then releases newest
  first. Each release shows version, a Current pill, date and change count, and
  expands to a one-line summary plus its changes labelled New / Improved /
  Fixed. The latest is open, older collapsed. A type filter opens matching
  releases and hides the rest. Reachable from Settings, About, the profile menu
  ("What's new") and the command palette.
- **Settings pages to the pattern.** Search, MCP and Audit move off the generic
  `row(label, help, control)` shape: lists become rows or cards with per-item
  actions, the section's **Add** moves to the section header, destructive
  actions separate from the primary, status becomes a pill (text plus colour),
  machine strings become mono with a truncate-plus-copy affordance, and every
  page defines empty, loading, error, off, long-text and success.
- **Contracts unchanged.** Only existing primitives (`src/components/ui.tsx`) and
  tokens (`src/index.css`) are used; no new class or component duplicates one
  that exists.
- **Gate.** The "Pre-Merge UI Checklist" in `DESIGN.md` is the review gate for
  any UI change from here on.

## MCP migrations

Additive only, so a 0.3.1 database upgrades in place with no user action.

- **Migration 17 — `mcp_servers.approval_mode`.** `ALTER TABLE ... ADD COLUMN`
  with a default that preserves today's behaviour (ask per call), then backfill
  existing rows explicitly so no server silently changes its policy.
- **Migration 18 — `mcp_servers.deny_tools`.** Nullable, additive. `allow_tools`
  already exists; an empty allow-list keeps meaning "no tools" (the v0.3.1 rule).
- **Migration 19 — `mcp_servers.ask_tools`.** Nullable, additive. Tool policy now
  resolves in one order: `deny_tools`, then `allow_tools`, then `ask_tools`, then
  the server's `approval_mode`; `mcp_set_policy` writes all three lists at once.
- **streamableHTTP needs no migration.** `transport` is already `TEXT`, so the
  new transport is a code change in `mcp.rs`; existing `stdio`/`sse` rows are
  untouched.
- **MCP page.** Rebuilt to the guide's pattern: numbered server list, one row per
  server with a status pill and per-server actions, Add in the section header,
  the approval callout above the list, and per-tool Ask / Allow / Block editing.
- **Crate.** The advertised MCP client version keeps tracking the `rmcp` crate
  version, as in 0.3.1.

## Issue fixes

- **#10 — review follow-ups.** The `knowledge_docs` delete keyed on `chat_id`
  was dropped: knowledge is project-scoped, so the statement never matched and
  deleting a chat must not remove project knowledge. `log_audit` now trims
  `audit_log` to the newest 500 rows instead of relying on the UI's view, and
  `split_segments` is a quote-aware scanner: it splits `;`, `|`, `&&` and `||`,
  splits inside `$(...)`, and stops at separators inside quotes.
- **#13 — images lost on regenerate / edit-resubmit.** Migration 20 adds
  `messages.attachments`, holding the images a turn actually sent. The payload is
  rebuilt from those parts, so regenerate and edit-resubmit keep their images and
  `hasImages` still routes to the vision model; the transcript renders them too.
  Exports still carry text only.
- **#15 — skill sanitizer hardening.** A dangling boundary prefix with no closing
  `>` is neutralized in both the Rust and TS sanitizers, so assembly cannot
  complete it into a live tag, and `skill.description` runs through
  `stripBoundaryTags` before it reaches the system prompt. A complete tag stays
  the tag stripper's job, in both implementations. The slash-boundary content
  loss stays: reverting it reopens the `<file/x>` bypass.

## Tool output controls (`D19`, code-mode Phase 0)

The model gets optional limits on the tools that used to dump everything into
context, and every affected result reports `{shown,total,truncated}`:

- **`web_fetch`** — `grep` (case-insensitive) keeps matching lines, `start` plus
  `max_chars` (default 8,000) page through a long page and a truncated result
  names the offset to continue from, `format: text` drops markdown syntax.
- **`web_search`** — `max_results` (default 5; `count` stays as an alias) and
  `fields` (`title`, `url`, `snippet`). The request asks for a few extra hits so
  the report can say more exist.
- **`run_powershell`** — `grep`, `head`/`tail` and `max_chars` (default 6,000)
  shape the output after the command finishes.
- **`recall_memory`** — `limit` is reported, and the query probes one row past it.
- **Shared shaping** — ANSI escapes and repeated blank lines are stripped in Rust
  before counting, the default caps are the model's unless it asks for more, and
  output over 32 KB still spills to disk.

## Upgrade path (from 0.3.1)

- Migrations are append-only: 17–20 are added, 1–16 are never edited or
  renumbered.
- Additive DDL only — `CREATE TABLE IF NOT EXISTS` and
  `ALTER TABLE ... ADD COLUMN ... DEFAULT`; no table rebuild, no column drop, no
  rename. Migration 20 only adds the nullable `messages.attachments` column, so
  existing chats keep their text and simply have no stored images.
- Backfill ships inside the same migration, so an existing `mcp_servers` row
  keeps its name, transport, target, allow-list and enabled flag.
- **Test.** A fixture database at schema 16 with real connections, projects,
  chats, memories and MCP servers is opened by the 0.3.2 build; after migration
  every row is intact, the new columns hold their defaults, and the MCP servers
  still connect and list tools.
- Downgrade is not supported: a 0.3.2 database opened by 0.3.1 is untested.

## Not in this release

- Code-mode Phase 1 (result handles) and Phase 2 (`execute_js` sandbox) — see
  `docs/plan/code-mode-migration.md`. Gated on measured intermediate-token use.
- Image attachments in exported chats: the export format stays version 1 and
  text-only, so stored images are not written to a chat export.
- Anything requiring a new key on the renderer side; keys stay in the vault.
