# Release v0.3.2 — design system pass, MCP migrations, issue fixes (minor)

Minor release: the design system becomes binding (and gains the Changelog page),
MCP storage gains an additive migration path, and the three open review issues
are closed out. No breaking change for existing installs.

## Scope

| # | Area | Tracked as |
|---|---|---|
| 1 | Design system pass (settings pages, Changelog page) | `G8` |
| 2 | MCP schema migration + MCP page | `J12` |
| 3 | Issue fixes | #10, #13, #15 |
| 4 | Tool output controls (code-mode Phase 0) | `D19` |

## Design changes

`DESIGN.md` is now the system of record and this release brings the settings
surface up to it.

- **Changelog page (`G8`).** New settings section between Shortcuts and About:
  an installed-version card with **Check for updates**, then releases newest
  first. Each release shows version, a Current pill, date and change count, and
  expands to a one-line summary plus its changes labelled New / Improved /
  Fixed. The latest is open, older collapsed. A type filter opens matching
  releases and hides the rest. Reachable from Settings, About, the profile menu
  ("What's new") and the command palette.
- **Settings pages to the pattern.** Search, MCP and Audit move off the generic
  `row(label, help, control)` shape: lists become rows or cards with per-item
  actions, the section's **Add** moves to the section header, destructive
  actions separate from the primary, status becomes a pill (text plus colour),
  machine strings become mono with a truncate-plus-copy affordance, and every
  page defines empty, loading, error, off, long-text and success.
- **Contracts unchanged.** Only existing primitives (`src/components/ui.tsx`) and
  tokens (`src/index.css`) are used; no new class or component duplicates one
  that exists.
- **Gate.** The "Pre-Merge UI Checklist" in `DESIGN.md` is the review gate for
  any UI change from here on.

## MCP migrations

Additive only, so a 0.3.1 database upgrades in place with no user action.

- **Migration 17 — `mcp_servers.approval_mode`.** `ALTER TABLE ... ADD COLUMN`
  with a default that preserves today's behaviour (ask per call), then backfill
  existing rows explicitly so no server silently changes its policy.
- **Migration 18 — `mcp_servers.deny_tools`.** Nullable, additive. `allow_tools`
  already exists; an empty allow-list keeps meaning "no tools" (the v0.3.1 rule).
- **streamableHTTP needs no migration.** `transport` is already `TEXT`, so the
  new transport is a code change in `mcp.rs`; existing `stdio`/`sse` rows are
  untouched.
- **MCP page.** Rebuilt to the guide's pattern: numbered server list, one row per
  server with a status pill and per-server actions, Add in the section header,
  the approval callout above the list, and per-tool allow / deny editing.
- **Crate.** The advertised MCP client version keeps tracking the `rmcp` crate
  version, as in 0.3.1.

## Issue fixes

- **#10 — review follow-ups.** Thread `chat_id` through `ingestDoc` so the
  `knowledge_docs` delete is real (or drop the dead statement), cap the audit log
  in `log_audit` instead of relying on the UI's 500-row view, and extend the
  PowerShell segment splitter to cover `|`, backticks, `$(...)` and quoted `;`
  (or document the limitation next to the rule).
- **#13 — images lost on regenerate / edit-resubmit.** Persist image parts with
  the user message (schema + `db.addMessage`) or add a read counterpart to
  `spill_image_write`, so a rebuilt payload still carries its images and
  `hasImages` routes to the vision model.
- **#15 — skill sanitizer hardening.** Neutralize a dangling boundary prefix with
  no closing `>` so assembly cannot complete it into a live tag, and run
  `skill.description` through `stripBoundaryTags` before it reaches the system
  prompt (Rust and TS kept aligned). The slash-boundary content loss stays:
  reverting it reopens the `<file/x>` bypass.

## Upgrade path (from 0.3.1)

- Migrations are append-only: 17 and 18 are added, 1–16 are never edited or
  renumbered.
- Additive DDL only — `CREATE TABLE IF NOT EXISTS` and
  `ALTER TABLE ... ADD COLUMN ... DEFAULT`; no table rebuild, no column drop, no
  rename.
- Backfill ships inside the same migration, so an existing `mcp_servers` row
  keeps its name, transport, target, allow-list and enabled flag.
- **Test.** A fixture database at schema 16 with real connections, projects,
  chats, memories and MCP servers is opened by the 0.3.2 build; after migration
  every row is intact, the new columns hold their defaults, and the MCP servers
  still connect and list tools.
- Downgrade is not supported: a 0.3.2 database opened by 0.3.1 is untested.
