# Release v0.3.4 — image capability and model selection (patch)

Patch release with no schema change. Two reported defects: a vision-capable model
was told it cannot see images whenever its provider did not report image support,
and the Settings model lists only ever showed the active provider, with a vision
fallback that accepted models that cannot see. `v0.4.0` stays reserved for the
sandbox release.

## Scope

| # | Area | Tracked as |
|---|---|---|
| 1 | Image capability detection and the per-model override | `F4`, `C3` |
| 2 | Cross-provider model selection and a vision-only fallback | `C2`, `F4` |

## What changed

### A model with no reported capability is no longer treated as blind

Routing was decided by `supports_vision === true` alone, so any provider whose
`/models` payload carries no modality (agentrouter, most custom base URLs) made
**every** model read as blind. The send path then stripped the image parts and
the backend injected "the current model cannot see images … call
`describe_image` … never claim to see the images directly", which pushed a
capable model into the fallback tool.

- Capability is now tri-state. A catalog flag wins when it is present; otherwise
  a known-family table answers (`gpt-4o`/`gpt-4.1`/`gpt-4-turbo`/`o3`/`o4`/
  `gpt-5`, `claude-3/4`, `gemini`, `gemma-3`, `llama-4`, `llama-3.2-vision`, any
  `-vl`/`vision`/`pixtral`/`llava`/`internvl` id → sees; `deepseek-chat`/
  `reasoner`/`coder`, `o1-mini`/`o3-mini`, plain `gpt-4`/`gpt-3.5`,
  `llama-2`/`llama-3.x`, `mixtral`, `mistral-small`/`nemo`, `phi-3/4`,
  `gemma-1/2`, Qwen text models, `grok-1/2` → does not); anything else is
  **unknown**.
- Unknown now means "can see": images are sent rather than silently stripped, so
  the failure mode is the provider's own error instead of a model that is told
  it is blind. `Settings → Models → Image reading` overrides a single model to
  **Can see images** or **Cannot see images** when detection is wrong; the
  override wins over both the catalog and the table.
- Only a model that cannot see is routed to the fallback and only such a model
  is offered `describe_image`; a seeing model no longer gets the tool in its
  request at all.
- The fallback request now runs on the **fallback model's own connection**
  (`base_url` + vault key) instead of the active chat's provider, so a fallback
  may live on a different provider.

### Settings → Models spans every provider

- Both lists were fed by the active connection's models, and the vision fallback
  offered the whole list, so a text-only model could be chosen as the reader.
  The page now loads models and capacities from every configured provider
  (connections without a stored key are skipped) and groups them by provider;
  picking a default model switches the active provider.
- The vision fallback lists only models whose capabilities say they can see, and
  stores `{connectionId, model}`. The old bare-model value is still read, and a
  value stored without a connection resolves to the active provider, so there is
  nothing to migrate.

## Tests

- `src/lib/catalog.test.ts` — catalog flag wins; the family table's positive and
  negative families, including text-only siblings such as `o3-mini` and plain
  `gpt-4`; an unknown model is treated as able to see; the override decides in
  both directions.
- `src/lib/vision.test.ts` — the stored fallback round-trips with its
  connection, a legacy bare model reads as the active connection, clearing
  removes both keys, and overrides store, apply, clear, and ignore an
  unrecognised value.
- `src-tauri/src/llm.rs::describe_image_tool_is_listed_and_gated` — the spec is
  present for a blind model and absent for a seeing one.

## Upgrade path (from 0.3.3)

- No migration. The schema stays at 20; 0.3.3 and 0.3.4 databases are
  interchangeable.
- No stored data changes shape. The vision fallback keeps working with its
  existing `visionFallbackModel` value, which is read as "active provider".
- Downgrade is untested, as before.

## Not in this release

- Attachments outside a project and real PDF text extraction (`F3`); the
  composer still needs a project for a non-image file.
- Everything planned for `v0.4.0` (sandbox, decision models, voice, subagents,
  research) — see `docs/releases/v0.4.0.md`.
