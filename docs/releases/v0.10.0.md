# Release v0.10.0 - Generative UI, artifact scripts and readable code blocks

Status: release candidate on 2026-11-06. Follows v0.9.3. No migration.

## What changes

- A fenced `openui-lang` block renders as native app components through
  `@openuidev/react-lang` instead of markdown. The curated library is `Stack`,
  `Row`, `Card`, `Text`, `Stat`, `Table`, `List`, `Callout`, `Progress`,
  `BarChart`, `Button`, `FollowUps`, `KeyValue` and `Code`. The generated prompt
  is appended to the system prompt while Generative UI is on; the switch lives
  in Settings → General and defaults on. Unknown components are dropped by the
  parser, an unclosed fence streams, and a failed parse shows the source. Buttons
  send a new turn or open an `https:` link; there is no Query, Mutation or
  `toolProvider` bridge.
- Every code block gets the same chrome. Unknown, unlabelled and `text` fences
  now show a language label, a Copy button, a border and a background instead of
  looking like ordinary prose. Code inside a block no longer inherits inline-code
  padding.
- HTML artifacts run inline JavaScript again. Rust keeps up to eight 2 MB
  artifacts and serves a per-artifact shell from the `artifact` protocol
  (Windows `https://artifact.localhost/s/<id>`) with
  `default-src 'none'; script-src 'unsafe-inline'; connect-src 'none'` and the
  rest of the preview policy. The shell JSON-escapes the untrusted markup and
  puts it in a nested `sandbox="allow-scripts"` `srcdoc` iframe. Scripts, canvas
  and data images work; the artifact cannot read the app document, storage or
  Tauri IPC, open popups, navigate the top frame, or use fetch/XHR and
  WebSockets. WebRTC is not covered by CSP. The app CSP adds `frame-src` for the
  shell, and thumbnails keep their script-free path.
- Artifact names come from the content. An HTML fence uses `title="…"` in the
  fence metadata, then `<title>`, then the first `<h1>`, then `HTML preview`;
  duplicates get ` 2`, ` 3` and so on. The drawer and Download use that name
  instead of `artifact.html`, and `save_artifact` now asks for a specific 2–5
  word title.

## Verification

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`,
  `npx tsc --noEmit`, `npm test`, `npm run build`, `fallow dead-code`.
- New tests cover the OpenUI prompt and a rendered card/table, streaming and
  closed `openui-lang` fences, unknown and unlabelled code blocks, artifact name
  extraction and dedupe, and the artifact shell's escaping and CSP.

## Not in this release

- OpenUI forms, live queries, `Mutation`/`@Run`, charts beyond a horizontal bar,
  per-message edit mode and a model-validity guarantee.
- Per-artifact browser origins, artifact persistence, WebRTC exfiltration and a
  hard CPU watchdog for a runaway artifact loop.
