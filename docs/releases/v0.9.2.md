# Release v0.9.2 - Memory approval and prompt budget corrections

Status: release candidate on 2026-11-06. Follows v0.9.1. No migration.

## What changes

- Approving a memory now makes it reach the model. The approval previously kept
  the pending row's untrusted flag, and 0.9.1 stopped sending untrusted notes,
  so an approved note could never appear again. Approval promotes the note to
  trusted, which is what the user asked for by pressing Save.
- Import keeps provenance. A note exported as untrusted is imported as
  untrusted instead of being rewritten as trusted.
- A short one-word hold is no longer rejected as too short. The capture checks
  run on the raw recording; silence is trimmed only before transcription.
- A provider transcription that comes back blank now says "No speech detected"
  instead of showing an `upstream error:` prefix.
- The prompt keeps the skill index ahead of attached documents when both cannot
  fit, matching the 0.9.0 order.
- A single instruction longer than the prompt budget is cut at a word and
  labelled, instead of losing its body behind its heading.
- Durable memory is trimmed only to whole notes, never to a heading with no
  content, and the over-budget line counts blocks that were dropped whole.

## Verification

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`,
  `npx tsc --noEmit`, `npm test`, `npm run build`, `fallow dead-code`.
- New tests cover the skill index ahead of a document, the word-boundary
  truncation, and a durable block that must never keep a heading without a note.

## Not in this release

- The project Context pool stays for 0.10.0.
- The Settings memory counters still count every stored note rather than the
  notes actually sent; the context inspector is the accurate view.
