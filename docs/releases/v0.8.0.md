# Release v0.8.0 - MCP runtime details and computer-use trust

Status: release candidate on 2026-10-30. Follows v0.7.1. No migration.

0.8.0 finishes the work 0.7.0 deferred: the MCP runtime reports real phases,
the protocol metadata is surfaced, and computer use learns where an app's window
actually is, whether the user took over, and what it is allowed to type into.

## What changes

### MCP runtime

- Servers track an explicit runtime phase (`disabled`, `starting`, `ready`,
  `busy`, `needs_auth`, `needs_review`, `failed`, `stopped`) and typed error
  kinds with a next action; server details show the error and next action.
- `server/discover` is probed first and falls back to `initialize`; the
  negotiated protocol revision is shown in server details.
- `tools/list` honours `ttlMs` and `cacheScope`, and revalidates on
  `notifications/tools/list_changed`.
- A server details panel shows tools, logs, config and protocol, and the
  settings form validates the same config parser as the JSON editor.

### Computer use: correct window targeting

- `get_state` binds a snapshot to the exact window handle, so a later click can
  no longer resolve into a different window of the same app.
- Chromium and Electron windows expose only browser chrome from the top-level
  window. The server now walks the renderer window
  (`Chrome_RenderWidgetHostHWND`), which returns the real page tree:
  document, text fields and buttons with their screen bounds.
- When a page tree is still unavailable, `get_state` reports
  `page_tree_unavailable` with a hint, and element typing is refused with
  `chromium_content_unavailable` instead of silently typing into the address
  bar.
- Screenshots target the requested window: a foreground window is captured from
  its screen region, and a covered window uses `PrintWindow` instead of showing
  whatever is in front of it.
- Coordinate clicks raise the window and refuse with `not_foreground` unless
  the window is really foreground, then verify the click point is inside the
  window; an element click also verifies the point resolves inside that
  element (`click_target_mismatch`).

### Computer use: trust and safety

- The executable publisher is verified with Authenticode and cached; a
  mismatch blocks the app with `publisher_mismatch`.
- User takeover is detected with `GetLastInputInfo` and pauses the run with
  `yield_to_user`.
- App-only typing in a Chromium window requires `confirm=true`, because the
  focused control cannot be verified there.
- Password fields are detected by the password pattern and by label text
  (`password`, `passwd`, `passcode`, `pwd`, `secret`) for both focus and click
  points.

### Eval harness

- `scripts/computer-use-eval.mjs` runs the observe and action set against real
  apps: Notepad, a Chromium form, a long page, and the hard-deny, stale
  snapshot, secure attention, publisher, kill-switch, dry-run and budget paths.
- Each run writes a desktop screenshot when a task fails, window screenshots
  for selected steps and JSON results, restores the real config and audit log,
  and exits non-zero when any task fails.
- The Chromium form proves the click reaches page content: the page records the
  typed value and the submit click in its own title.

## Not in 0.8.0

- The optional local navigator (J14) is not shipped. The jevos-v5 binary and
  model install and answer `/v1/systemone`, but the benchmark gate needs a
  calibrated labelled set that was not built, so tier 2 stays out rather than
  shipping unmeasured.

## Tests

- Rust tests cover password detection, publisher policy, publisher fingerprints
  and targeting helpers.
- `npx tsc --noEmit`, `npx vitest run`, `cargo fmt --check`,
  `cargo clippy --all-targets -D warnings`, `cargo test`.
- `node scripts/computer-use-eval.mjs` against a live desktop.
