# Release v0.9.3 - Memory capacity scales with the model

Status: release candidate on 2026-11-06. Follows v0.9.2. No migration.

## What changes

- The memory budget scales with the model's context window. A 128k window keeps
  the 6,000-character prompt; 200k doubles it, 500k triples it, and 1M quadruples
  it, capped at 24,000 characters. Attached knowledge and past-chat snippets
  grow by the same factor, so a large-window model can read more of a document
  before falling back to a tool call.
- Durable notes keep their existing 2,500-character selection. The window buys
  room for documents and past chats, not for sending every stored note.
- The system prompt now tells the model how to ask for more: `read_document`
  with a document name for the rest of a project file, and `recall_memory` with
  a fresh query for notes it has not seen. This is the fetch half of capacity,
  and it needs no new tool.
- The context inspector shows the budget and its multiplier, so it is visible
  why a turn carries more than the old 6,000 characters.
