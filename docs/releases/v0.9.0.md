# Release v0.9.0 - Hybrid memory, project knowledge, past-chat search

Status: release candidate on 2026-11-05. Follows v0.8.8. No migration.

## What changes

- Memory retrieval is hybrid. `memory/index.rs` derives `memory_docs`,
  `memory_fts` (FTS5/BM25) and `memory_vectors` (MiniLM-L6-v2 INT8, 384d) from
  the markdown files, which stay the source of truth. BM25 and cosine are fused
  with RRF (k = 60); a vector-only hit must clear cosine 0.88. Each send ranks
  up to four notes and injects them as `## Relevant memory for this turn`.
- Project knowledge is chunked. Documents split at Markdown headings and
  1,000-character windows with 150 of overlap, then index into
  `knowledge_chunks`, `knowledge_chunks_fts` and `knowledge_vectors`. Up to
  three chunks (2,400 chars) are injected as `## Attached knowledge` with
  `doc`, `chunk` and `heading` attributes. Uploads reindex in the background,
  the Docs panel reindexes on demand, and a document or project delete purges
  its rows before returning.
- Past chats are searchable. `message_fts` is an FTS5 external-content index
  over `messages`, kept current by triggers, backfilled once behind a `meta`
  marker. `conversation_search` returns title, date, role and a snippet; project
  chats also get up to two earlier snippets as `## Earlier conversations`.
  A global chat never reads project messages.
- The write gate is stricter. Negated and interrogative requests no longer
  count as explicit saves, attached-document text cannot trigger one, an
  untrusted turn can only queue a note, and an explicit save is not lost to
  another chat's pending row.
- Every injection is explainable. `memory_retrieval_audit` records one row per
  injected item with its score, kept 30 days; the context inspector shows the
  score, the document section and the chat date, and says why a section is
  empty. `npm run eval:memory` gates recall@5 at 0.85 over
  `fixtures/memory/probes.json`.
- Voice transcription is fixed. Screening, voice and memory embeddings share
  one ONNX Runtime environment; screening degrades to no screen instead of
  panicking when the environment cannot be built.
- MCP OAuth sign-in completes. The probe sends protocol 2025-06-18, accepts a
  403 challenge, retries discovery without the challenge header, tags each
  failing step, and sign-in is reachable from the server row and details
  dialog. A mock authorization server test covers discovery, DCR, PKCE, the
  loopback callback and the token exchange.

## Verification

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test` (438 tests), `npx tsc --noEmit`, `npm test` (489 tests),
  `npm run build`, `fallow dead-code`, `npm run eval:memory` (recall@5 1.00).
- MCP OAuth checked live against Airtable: discovery, DCR, PKCE authorize URL
  with `resource` and the seven PRM scopes.

## Not in this release

- Consolidation (near-duplicate merge, contradiction flags) and the jev
  verifier stay for a later slice.
- 1.0.0 keeps its own gate: clean-machine eval and the security review.
