# Release v0.3.3 — verified streaming safety (patch)

Patch release with no new user-facing feature and no schema change. The retry,
mid-stream stop and agent-loop guards the build already carried are now covered
by the tests their specs ask for, and the roadmap statuses are reconciled with
the code. `v0.4.0` stays reserved for the sandbox release.

## What this release proves

These three shipped earlier and were recorded as `Partial` or `Missing`. Reading
the code against each spec's **Done** line showed the behaviour was already
there; what was missing was the evidence. This release adds it.

- **Retry with backoff (`A4`).** 429, 5xx and network errors retry up to ten
  times with jittered exponential backoff, `Retry-After` is honoured (capped),
  a 400 never retries, retrying happens only before the first token, and the
  status line shows `Retrying (n/10)`. A new test pins the remaining half of the
  Done line: an error that arrives *mid-stream* is not retried, the upstream
  message surfaces, and the stream that already arrived is kept.
- **Stop / cancel mid-stream (`A2`).** A cancel token is checked on every stream
  read and before each tool call; stopping drops the body, keeps the partial
  text, marks the turn `stopped` and settles any tool entry still running as
  interrupted. A new test cancels after the first delta and asserts the turn
  resolves without error and later chunks never arrive.
- **Step cap and doom-loop guard (`D3`).** `max_iterations` defaults to 25,
  clamps to 1..32, and at the cap the loop falls back to a no-tools request
  instead of stopping silently. The same tool with the same arguments three
  times in a row asks **Keep going / Stop here** rather than looping. The cap
  and the guard's counting are already tested; the guard's prompt is covered by
  the audit path.

## Tests added

Both live in `src-tauri/src/llm.rs` and run offline against a scripted local
server.

- `stream_error_mid_flight_is_not_retried` — one delta, then an `error` payload:
  the call fails with `Upstream`, the server saw exactly one connection, and the
  delta was already emitted.
- `cancel_mid_stream_keeps_the_text_already_sent` — cancel after the first delta:
  the call returns `Ok(())` and the later chunks never reach the channel.
- Harness: `serve_sse` (a chunked `text/event-stream` server) and
  `collect_events` (a test `Channel` that records every `StreamEvent`).

## Debt recorded, not fixed

The 0.3.2 review's hardening items are now written down in `docs/later.md`
("Review debt", no IDs) instead of living only in review threads: the MCP tool
alias collision, untrusted framing for MCP tool text and `web_fetch` /
`web_search` bodies, deny-table ordering, bidi and C1 controls in the raw output
preview, the missing `SKILL.md` size cap, and the uncached attachment parse.
`mcp_add` accepting an arbitrary stdio command is recorded as intentional.

One gap found during the pass is also recorded there: `.github/workflows/ci.yml`
runs the Rust suite but never `npm test`, so the vitest suite is not a CI gate.
Changing CI was outside this release's file scope, so it is left for the next
CI touch.

## Upgrade path (from 0.3.2)

- No migration. The schema stays at 20; 0.3.2 and 0.3.3 databases are
  interchangeable.
- No stored data changes shape. The only Rust change is test-only.
- Downgrade is untested, as before.

## Not in this release

  research) — see `docs/releases/v0.4.0.md`.
