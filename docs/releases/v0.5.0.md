# Release v0.5.0 — memory as one file (minor)

Shipped 2026-10-23. The v0.4.1 upgrade fixture passes end to end
(`migration_tests::a_0_4_1_database_migrates_memory_into_a_file_once`).
Follows v0.4.1. Design and failure matrix: `docs/plan/v0.5.0-memory-file.md`.

Besides the memory move, this release closes the 0.4.1 ledger: two UI
regressions and the parts of that plan that never shipped. Provider key
rotation is explicitly deferred to 0.6.0.

## E1. Memory becomes a file
- Two scopes: `memory/MEMORY.md` (global) and `memory/projects/<uuid>.md`
  (one per project, only when it has notes).
- Four headings — User, Preferences, Project, Decisions. One bullet per note;
  id and date in a trailing HTML comment, so nothing but the note costs tokens.
- Metadata is stripped before injection. 2500 chars per scope, and Settings says
  "N notes not sent" whenever the cap drops lines.
- Hand edits apply on the next send (mtime check, no watcher). A read failure
  uses the last good render and never blocks a send.
- Done: an external edit shows up next turn; a note cannot forge metadata;
  the app runs with no file, one file, and a corrupt file.

## E6. The inbox stays the gate
- `remember` still writes to `pending_memories`. Approve appends the line,
  dismiss drops the row, undo removes the line and restores the pending row.
- Nothing unreviewed ever enters the file, so the judge is not needed to make
  this safe.
- Done: no line exists before approval; undo returns the exact pending row.

## E2. Secret refusal and source trust
- `looks_secret()` runs before every write: `sk-`, `ghp_`, `AKIA`, long
  hex/base64 blobs, private-key headers, `password=`, `token=`, `Bearer`.
- A candidate from a turn that called `web_search`, `web_fetch`,
  `knowledge_search`, `sandbox_run`, `sandbox_read`, `sandbox_glob`,
  `sandbox_grep`, `run_powershell`, `describe_image`, `read_document`,
  `delegate_task` or any `mcp__*` tool is tagged **untrusted** and can never be
  auto-accepted. Rust reads this from the tool log, so the model cannot spoof
  it. The tag survives in the file comment.
- Duplicates are dropped against both the target file and the inbox.
- Filters can only drop, never approve.
- Done: "remember this sk-…" is refused with a reason; a web-sourced candidate
  is untrusted.

## Migration from 0.4.1
- Three additive SQL migrations: **27** adds the audit `duration` / `exit_code` /
  `source` columns (S4b), **28** adds `meta(key, value)`, **29** adds
  `pending_memories.trust`. No `UPDATE`, no `DELETE`, no `DROP` in the whole
  release.
- First launch: backup `memory/legacy/memories-<utc>.json` → atomic file writes
  → `legacy/unassigned.json` → marker. A failure before the backup leaves the
  0.4.1 database untouched.
- File existence is the idempotency key, not the marker. A lost marker cannot
  duplicate notes; an existing file is never overwritten.
- `memories` is frozen, not dropped — it is the rollback snapshot.
  `pending_memories` is untouched, so the inbox survives the upgrade.
- If migration cannot run, reads fall back to `memories` and the UI shows a
  compatibility banner. Memory degrades, it never disappears.
- Orphan project notes (deleted or missing project) go to
  `legacy/unassigned.json` plus a banner; they are never promoted to global.
- Done: a fixture covering every row case (long, multi-line, duplicate, unknown
  kind, orphan) imports with matching ids and text; a second launch is a no-op;
  killing the app mid-migration loses nothing.

## Upgrade path (what the user sees)
1. Install 0.5.0 over 0.4.1 and open the app.
2. One dialog: "Memory moved to a file." with counts, the backup path, and
   "Open MEMORY.md" / "Review N unassigned".
3. Settings → Memory now edits the file itself, with a conflict guard when the
   file changed on disk since it was opened.
4. Downgrading to 0.4.1 shows memory as of the upgrade. Notes added on 0.5.0
   come back after re-upgrading through **Import** with a 0.5.0 export: ids are
   kept, so notes already in the file are skipped rather than duplicated.
5. "Delete everything" removes `memory/`, backups included.

## Not in this release
- Provider key rotation (S8). 0.6.0, with skip + 10-minute cooldown.
- Generic permissions, YOLO mode, recent models and the OpenCode provider.
  Parked in `docs/later.md`.
- Local judge model (ONNX), its calibration, and any auto-write band. 0.6.0.
- Consolidation of near-duplicates. A suggestion action only, later, and never
  automatic.
- File watcher, semantic retrieval, and per-workspace memory folders (projects
  have no path in this app).

## Tests and gate
- Rust: parse/render round-trip (hand text, unknown comment, CRLF, BOM,
  `<!--` escape), atomic write, path jail, stale-mtime rejection, migration
  fixture, idempotent second run, lost-marker no-duplicate, missing model file,
  audit-column migration on an old row.
- Vitest: bootstrap migrates before `refreshMemories`; failure shows the banner
  and still opens chats; `wipeAll` clears `memory/`; export carries markdown;
  one placement helper returns a single pill; an export/import round-trip
  recreates the same rows; the DeepSeek table resolves a window.
- Gate: `npx tsc --noEmit`, `npm test`, `npm run build`,
  `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`,
  `fallow dead-code`, plus OCR.
- Manual: upgrade a real 0.4.1 database; edit in Notepad between turns; delete
  the file while open; make it read-only; kill mid-migration; scroll a long chat
  and confirm the jump button holds; watch one turn and count the pills.
