# Release v0.6.0 — MCP authorization and Streamable HTTP (minor)

Status: shipped with v0.6.0 on 2026-10-26. Follows v0.5.1. Migration 30.

Online MCP servers are now usable without a third-party bridge. 0.6.0 replaces
the hand-rolled `2024-11-05` client with the official Rust SDK (`rmcp` 3.7.0),
adds OAuth 2.1 and bearer-token authorization, and stores tokens in Windows
Credential Manager. Existing stdio servers, approvals, policy and tool
namespacing keep working.

## What changes

- **Streamable HTTP.** Initialize, `MCP-Protocol-Version`, optional
  `Mcp-Session-Id`, `notifications/initialized`, JSON or SSE responses, and a
  legacy `sse` fallback. The MCP dialog now offers `http` (Streamable HTTP)
  next to `stdio` and the legacy `sse` transport.
- **MCP hardening.** Tool results that are not text (images, audio, embedded
  resources, resource links, structured-only results) are described instead of
  silently becoming an empty result. Connected servers honour
  `notifications/tools/list_changed` and re-list their tools after five minutes.
  A handshake has a 20-second deadline, so a dead server cannot block the first
  send forever. The `rmcp` fallback now negotiates the latest protocol version
  that still supports `initialize`.
- **OAuth 2.1.** RFC 9728 protected-resource discovery, authorization-server
  metadata, dynamic client registration, PKCE S256, a loopback callback, token
  refresh, and local disconnect.
- **Callbacks.** Loopback `127.0.0.1` only in this release. The
  `myagent://oauth/callback` custom scheme is deferred.
- **Token storage.** A `CredentialStore` backed by Windows Credential Manager,
  chunked when the serialized credential exceeds one entry. Tokens never enter
  the webview or SQLite.
- **Bearer auth.** A write-only token field for PAT/API-key servers.
- **Auth states.** Not checked, connecting, waiting for browser, connected,
  authorization required, expired, failed. Reconnect and disconnect actions.
- **Migration 30.** `mcp_servers.auth_type` with default `none`; existing rows are
  unchanged. `transport` gains `http`; `sse` remains the legacy path.
- **Provider setup recovery.** Adding a provider no longer deletes the row when
  the first model check fails. The row stays, the exact key/base-URL/network
  error is shown in the dialog and on the provider card, and the user can retry,
  keep the provider or delete it explicitly. See
  `docs/plan/v0.6.0-provider-add.md`.
- **Ollama Cloud setup.** Verification now uses the documented
  `GET https://ollama.com/api/balance` bearer check instead of the undocumented
  `/api/me` probe, and model listing falls back to `https://ollama.com/api/tags`
  when `/v1/models` is unavailable.
- **Composer layout.** The hold-to-talk mic now sits beside Send instead of at
  the far left of the composer toolbar.
- **Onboarding.** First run is four steps: welcome and display name, provider,
  model, and search/suggestions. Each step can be skipped, and the provider step
  keeps the row when the first model check fails so the key can be corrected.
- **Key rotation.** Up to ten keys per provider connection. A quota or billing
  rejection skips to the next key and cools the rejected key down for ten
  minutes; plain rate limits keep the existing backoff. Providers lists every
  stored key, shows a cooling key, and can remove one key or all keys. The
  feature promised in 0.4.1 S8 and deferred from 0.5.0 is now shipped.
- **AgentRouter GPT retries.** A `content-blocked` 400 from AgentRouter's gateway
  is retried twice with backoff and then reported as an AgentRouter moderation
  block, not a model decline. AgentRouter's WAF can reject an otherwise valid
  prompt; the app names the gateway and asks you to rephrase or start a new
  chat.
- **Model catalogue cache.** The backend catalogue cache and the model picker
  both keep model lists for ten hours. Reopening the picker no longer waits on
  every provider; Refresh on the Models page, saving a provider, deleting a
  provider, or a successful provider test invalidates the cache.

## What does not change

- Tool approvals, deny rules, audit rows and namespacing.
- Memory files and the 0.5.0 migration.
- The chat/title/summary paths fixed in 0.5.1.
- No MCP server mode, no enterprise SSO, no hosted CIMD document yet.
- No pre-registered OAuth client fields, no custom-scheme callback, and no
  server-side token revocation in this release. Disconnect clears the local
  credential and requires a new browser sign-in.

## Upgrade path

Install 0.6.0 over 0.5.1. Existing stdio and `sse` servers keep their rows and
default to `auth_type = 'none'`. A server that needs OAuth shows
"Authorization required"; choose OAuth, connect, finish in the browser, and the
tool list refreshes. A server that needs a PAT uses the bearer field. No tool
permission is widened by the upgrade.

## Security

- `rmcp` 3.7.0 or newer; CVE-2026-63127 and CVE-2026-64684 are below the floor.
- PKCE S256, `state`, exact redirect URI, five-minute callback timeout.
- OAuth resource URLs are HTTPS, except loopback HTTP. Authorization URLs opened
  in the browser must be HTTPS or loopback HTTP and cannot embed credentials.
- RFC 8707 resource binding; no token is sent to a different host.
- Tokens only in Credential Manager; oversized blobs are chunked. Never in
  SQLite, logs or JS.
- A 401 never silently retries unauthenticated.
- Re-auth stores the new credential only after the callback succeeds.

## Manual MCP verification

Local fixtures on 2026-10-26:

| Server | Transport | Auth | Result |
|---|---|---|---|
| `manual-bearer` | `http` (Streamable HTTP) | bearer | Connected; `echo` listed |
| `manual-oauth` | `http` (Streamable HTTP) | OAuth DCR + PKCE | Connected after browser callback; `echo` listed |
| `manual-sse` | `sse` (legacy) | none | Connected; `echo` listed |

The OAuth fixture exercised protected-resource metadata, authorization-server
metadata, dynamic client registration, PKCE S256, the `127.0.0.1` loopback
callback, token exchange, and token storage. The bearer fixture rejected requests
without the token. All three servers reported `1 tool` and the tool list showed
`echo`; the MCP summary read `3 servers · 3 connected · 3 tools`.
