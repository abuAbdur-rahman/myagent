# Release v0.7.0 — MCP setup UX and Windows computer use

Status: planned. Target: 0.7.0. Follows v0.6.1. Migration 31.

0.7.0 turns MCP from a flat server form into a managed, inspectable subsystem,
then ships a bundled Windows computer-use server on top of it. It also fixes the
AgentRouter OpenAI Responses failure and restores visible reasoning where the
provider returns it.

## What changes

### AgentRouter OpenAI compatibility

- Responses requests are stateless: the full conversation is sent on every
  request, and stored item references / `previous_response_id` are not reused
  across requests. This avoids the Azure OpenAI "requested item was created
  under a different Azure OpenAI resource" 400 when a gateway routes to a
  different resource.
- Reasoning summaries/thinking parts returned by Responses are preserved and
  rendered instead of being dropped.
- Regression tests cover the stateless request builder, reasoning-part parsing
  and the AgentRouter fallback path.

### MCP setup and safety

- **Rust-owned server state machine:** `disabled`, `starting`, `ready`, `busy`,
  `needs_auth`, `needs_review`, `failed`, `stopped`. The UI renders state and
  sends intents; it no longer infers health from a probe.
- **Structured config:** command, args, cwd, env, URL, headers, transport, auth
  and timeouts. Standard `mcpServers` JSON import/export; project-scoped
  servers; app-only approvals, policies and tool hashes stay out of the portable
  file; secrets use `${secret:name}` and remain in Windows Credential Manager.
- **Windows process lifetime:** Job Object with `KILL_ON_JOB_CLOSE`, bounded
  stderr logs, non-protocol stdout rejection, and the existing `.cmd` shim
  resolution without building `cmd /c` strings from config text.
- **Protocol:** `server/discover` first, legacy `initialize` fallback, negotiated
  revision shown in details, `Mcp-Method` / `Mcp-Name` on Streamable HTTP,
  `tools/list` caching with `ttlMs` / `cacheScope`. Legacy `sse` stays while
  target servers need it.
- **Approval integrity:** the exact untruncated command is shown before first
  run; tool-definition hashes move a server to `needs_review` when they change;
  annotations are hints, not permission bypasses.
- **Settings UX:** server list with honest status pills and tool counts; add/edit
  with Form and JSON tabs and a stepped Test connection; details with Tools,
  Logs, Config and About; in-chat tool-call and approval cards; composer server
  chip; progressive disclosure for protocol, timeouts, headers, env and OAuth
  metadata URL. Protocol defaults to Auto.
- **Errors:** every failure has an error kind, a human message and a next action.

### Windows computer use

- Bundled Rust `computer-use` stdio MCP server, spawned by the MCP manager, never
  elevated.
- Observe first: `list_apps`, `list_windows`, `get_state` (compact UIA tree,
  optional screenshot) and `screenshot`; UI Automation first, pixels as fallback
  for canvas/Chromium/Electron apps.
- Actions: `invoke`, `click`, `type_text`, `set_value`, `press_keys`, `scroll`,
  `drag`, `wait`, `focus_window`, `launch_app`, and gated clipboard tools. No raw
  shell tool.
- Snapshot-scoped element ids; stale ids return `stale_snapshot`. Node/depth caps
  and physical-pixel coordinates with per-monitor DPI awareness v2.
- Per-app approval by executable path and publisher signature, with `View` /
  `Interact` / `Full` tiers. Hard denies for terminals, password managers,
  UAC/secure desktop, security tools and password fields.
- Kill switch, always-on-top control indicator, pause when the user takes over,
  action budgets, dry-run, before/after audit thumbnails and confirmation for
  irreversible actions.
- Settings: Computer use page with master toggle (off by default), app allowlist
  and tiers, hard-deny list, hotkey picker, overlay toggle and audit viewer.

## What does not change

- No macOS/Linux/mobile branches.
- No elevated agent, no secure-desktop input, no raw shell in the computer-use
  server, and no remote steering.
- No local screenshot/vision model; cloud vision only.
- Legacy `sse`, OAuth, bearer storage, tool namespacing and existing approvals
  keep working.
- The optional local navigator (`jevos-v5`) is not in 0.7.0; it is a gated 0.8.0
  experiment.

## Migration

Migration 31 adds structured MCP config and app-only state. Existing server rows
keep their name, transport, auth, command/URL, policies and tokens. The old
single `cmd` value is split into command and args without changing behavior.

  statelessness and reasoning parsing.
- Computer-use: UIA tree caps, stale snapshots, hard denies, kill switch,
  action budgets, audit rows, dry-run.

  `fallow dead-code`, `git diff --check`.
- Observe eval passes before action tools are exposed.
