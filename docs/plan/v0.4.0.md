## M1 — decision models (injection screen only; HAP moved to V1)

New `src-tauri/src/screen.rs`:

- `Screener` trait: `screen(text) -> Option<ScreenVerdict{label, score, suggest_deny}>`.
  CI tests use a fake; real model never load-bearing.
- `OnnxScreener`: `ort` 2.0.0-rc.15 + `tokenizers` 0.23 (`fancy-regex`
  feature, no onig). CPU EP, single session behind Mutex, inference on
  `spawn_blocking` with a 900ms budget; timeout/error → `None` (fail-open:
  approvals behave exactly as today).
- One model, one session: injection (deberta QUInt8). HAP (toxicity) deferred to
  V1 — warn-only, and only voice finals truly need it; the trait stays ready.
- **Escalate-only invariant**: the screen may add a warning but can never turn an
  Ask into an Allow and never auto-approves. Enforced structurally: the screen
  only runs inside the Ask branch, and `permissions::effective_reply` downgrades
  a flagged "always" to a one-time allow **before** any rule is persisted (test:
  `flagged_approvals_never_persist_always`).
- **Chunking**: model window is 512 tokens (English-only, risk noted by review).
  Text is split into ≤1500-char chunks; when there are more than 4, the first
  two and the **last two** windows are scored (head+tail sampling, so an
  injection appended after long prose is still seen) and the max wins. Docs
  quoting "ignore previous instructions" will false-positive — hence warn-only
  + human decision.
- Timeout/error/absent model → `None` (fail-open: approvals behave exactly as
  today). Model missing → screen simply never installs.

Seams (verified):

- Screen call: `llm.rs:1387`, inside the Ask branch right after
  `permissions::check` — never-silent-Allow holds by construction (the screener
  is loaded lazily there, not per turn). MCP-policy Allow bypasses the
  screen as designed today (recorded gap; revisit with S1 enablement).
- Card: extend `ApprovalAsked` (llm.rs:53) with
  `screen: Option<{label, score, suggest_deny}>` → Zod `types.ts:259`
  **`.nullish()`** (Rust serialises `None` as `null`) → store approval
  state → warn line under TurnCards.tsx:62. "Always allow" (and key `2`) is
  disabled when flagged; the warning line says the call can only be allowed once.
- Audit: `log_audit` decision `screen(flag)` / `hap(flag)`, score+label in
  `detail` (2000-char cap fine, no schema change). High-confidence flag
  suppresses "Always allow" persistence (once-only).
- Model lifecycle: settings toggle (Permissions section) → streamed download
  to `app_data_dir()/models/<name>/` via reqwest (stream feature is on) →
  SHA-256 manifest check (add `sha2`) → rename into place. **Hosting decided:
  GitHub release assets**, versioned with the app, pinned by SHA-256. Download
  is opt-in, shows size before consent, and is resumable (Range requests — no
  existing code has them; build it). No bundle in NSIS. First gated call pays
  lazy load after Enable.

Owner prep replaced by done work (2026-10-19):

1. DeBERTa: official fp32 ONNX downloaded from `protectai/...` at pinned
   revision `90c9989b...`, quantized and validated against fp32 on
   benign + injection samples (`C:\Users\abdul\myagent-models\prepare_injection_model.py`,
   `MANIFEST.json` with sizes + SHA-256). Ship `model_int8.onnx` + `tokenizer.json`
   as one GH release asset.
   - **QInt8 dynamic quantization is broken on DeBERTa-v3**: it inverts
     predictions (injections scored SAFE at 0.89–0.92). Caught by validation.
   - Working recipe: `quantize_dynamic(per_channel=True,
     weight_type=QUInt8, nodes_to_exclude=["/classifier/"])` → 244 MB,
     predictions identical to fp32 on all 8 probe samples (both miss the same
     borderline attack at 0.427).
   - Measured on this 4-core box: **~132 ms fp32 / ~138 ms QUInt8 per 512-token
     inference** — not the ~54 ms the scoping note claimed. Still inside the
     900 ms budget; a long tool call is scored as at most 4 chunks (head+tail).
   - DeBERTa-v3-small would be smaller but is a **gated repo (401)** — dropped.
2. HAP: deferred to V1; export from installed safetensors then.

Spike result (2026-10-19, this machine, throwaway crate in temp):

- `ort =2.0.0-rc.15` (`download-binaries`) builds and runs CPU inference on
  Windows; **rc.15 is the real latest** (investigation said rc.14 — wrong).
  API notes for `screen.rs`: `ort::init().with_telemetry(false).build()`
  once per process (rc.15 allows one Environment only — injection + HAP
  sessions must share it), `Session::builder(&env)?.commit_from_file(..)`,
  `Tensor::from_array(([1, N], vec))`, output `(&Shape, &[f32])`. No
  `ort::ndarray` re-export — use `Tensor::from_array` shape tuples.
- `tokenizers` 0.23 (`fancy-regex`) loads the installed HAP RoBERTa
  tokenizer.json and encodes; DeBERTa-v3 uses the same loading path.
- Measured: load + one inference of smart-turn ONNX works end-to-end.
- Risk found: pyke prebuilt ONNX Runtime binaries **require AVX2** (ort
  eprintlns a warning and then crashes with illegal instruction on non-AVX2
  CPUs). Screen must fail-open if the process would crash — check
  `is_x86_feature_detected!("avx2")` before creating the Environment and
  disable the screen with a settings note on older CPUs.
- Build/link verified on the real app: `ort` links ONNX Runtime **statically**
  (no `onnxruntime.dll` beside the exe; only an unused `DirectML.dll` is staged
  in `target/debug`, the CPU EP never loads it). Nothing extra to bundle in
  NSIS for M1. The prebuilt binaries do add ~1–2 min to a cold CI build.

Sizes: spike S (half-day, ort runs deberta on Windows) → runtime M →
download M → wiring+card+audit+tests S-M. Fail-open design means CI needs no
model files.

Tests: verdict/threshold/fail-open/timeout with fake screener (cargo);
assist-line render with and without screen (vitest); framing redaction unit
tests; real-model `#[ignore]` IT behind env flag (pattern:
`MYAGENT_SANDBOX_IT=1`).

## D18 — subagents

Spine: `EventSink` trait replacing `&Channel<StreamEvent>` in `RealModel`
(llm.rs:1229), `RealTools` (llm.rs:1282), `stream_agentic_iteration`
(llm.rs:1085), `stream_completion` (llm.rs:1669). Impls: `DirectSink`,
`ScopedSink{channel, parent_request_id, delegate_call_id}` wrapping child
events in `StreamEvent::Subagent{parent, event}`.

Spawn: `delegate_task` branch in `RealTools::run` before llm.rs:1517.
Child = `ChatRequest{request_id: "{parent}:d{n}", messages: [child system,
task + excerpts capped by truncate_chars 8000], max_iterations clamp 1..8,
project/conversation inherited}` → `run_agentic` with `ScopedSink`. Child
specs filtered: no `delegate_task` (depth 1); `ask_user`/memory writes stay
unless owner decides otherwise at build time. Result flows the existing
tool-result path (llm.rs:1564) → parent sees summary as tool output.

Traps to close (from investigation — the riskiest piece):

1. Child `Delta` must never reach the parent text buffer — frontend routes
   `subagent` events into the parent tool entry's preview only.
2. Cancel: `Notify::notify_one` wakes one waiter (state.rs:45) — add
   `register_child` + fan-out `notify_waiters()`; child
   `take_cancelled` checks the **parent** id only (flag is consuming,
   state.rs:62).
3. Frontend single-stream invariants (store.tsx:474,1625) untouched: child
   is never a second top-level stream; no second Channel.

Approvals surface once by construction (one global card; parent blocked in
the delegate await). Child audit rows reuse `log_audit` with the same
conversation id — one row per user-facing decision, as required.

Frontend: `parent?: string|null` on `toolLogEntrySchema` (types.ts:28 — Zod
strips unknown fields), subagent event routing (store.tsx:1292), nested render
inside the parent `<details>` (MessageList.tsx:136-164). Child system prompt:
`buildChildSystemPrompt` sibling in context.ts (identity + project block only),
set via `ChatRequest.child_system`. Model: `delegate_task.model?` validated
against `fetch_model_caps` supports_tools, fallback `req.model`.

Pre-reqs: cross-cutting #4 (SKILL.md cap), #5 (streamTurn e2e), #6
(filter_tools). Sequential children only for v1 (llm.rs:1211 is sequential).

Sizes: sink refactor M · spawn S-M · state registry S-M · child prompt S ·

## R1 — research job

One tool `research_run(query, …)` in new `src-tauri/src/research.rs`,
executed from `RealTools::run` like any tool: cancel, audit,
ToolStart/ToolResult cards, artifact plumbing free; costs 1 of 25 iterations.

Flow:

1. Plan: one cheap-model non-stream call (raw HTTP per
   `describe_image_via_fallback`, tools.rs:297) → queries + host candidates.
2. Pre-flight: one job-grant Ask card covering `web_search` for the job and
   the planned host list (new job-scoped grant — the only new permission
   plumbing; `web_fetch` per-host Ask kept where host not pre-granted).
3. Fetch loop: concurrency 2-3 over `websearch::search` +
   `webfetch::fetch_page` (max_chars 8K), dedupe; wall-clock / searches /
   fetches / token caps enforced Rust-side (`normalize_usage` sum, sse.rs:196).
   Excerpts → Rust-side notes buffer; full pages land in D13 spill.
4. Synthesize: main-model call over the **notes digest** — not history
   (`prune_tool_history` stubs old tool results every step, llm.rs:1256).
5. Result: memo as tool output + `StreamEvent::Artifact{lang:"markdown"}` —
   ArtifactsPanel renders markdown today; 200K cap.

Progress: re-send `ToolStart` same id (updates entry in place,
store.tsx:1341-1344 — zero FE change) + `refreshTodos` on `todo_*` result
(one-liner, store.tsx:1389 is end-of-turn only). Make `todo_write`/`todo_set`
default-Allow first (not in permissions.rs:178 default_rules → Ask per call →
prompt storm).

Task model: research-only setting for v1 (J5-lite; titles/compaction keep
chat model). Cancel → partial memo marked cancelled. Concurrent jobs: 1.

Sizes: orchestrator M-L (2-4d) · progress S · memo S · job-grant M ·

## V1 — voice transcription (PTT)

Capture: AudioWorklet with `AudioContext({sampleRate:16000})` → Float32 → i16
in JS → one `invoke audio_transcribe(bytes, …)` per PTT utterance (30s ≈ 1MB).
CSP `tauri.conf.json:24` blocks blob: URLs — worklet module ships as a real
file in `public/`. Spike the WebView2 mic `PermissionRequested` behaviour
first (known trap: microphone auto-deny on some runtimes); fallback =
`WebviewWindowBuilder::on_permission_request`. MediaRecorder rejected: never
16kHz, needs opus decode.

Rust: `transcribe-rs` (`onnx` feature) + installed Moonshine
medium-streaming quantized `.ort` — no sidecar, no C toolchain. Model dir =
`app_local_data_dir()/models/`; the already-downloaded files are copied or
re-pointed there on Enable (settings page mirrors S1 pull-on-enable consent
UX). tiny-streaming `.ort` = low-size option (the installed GGUF copy is the
wrong format — drop or re-download). Load lazily, unload after idle.

BYOK: new Rust command → `connections::base_url_for` + `endpoint(…,
"audio/transcriptions")` + `vault::get_api_key` (never in webview). Needs
`reqwest` `multipart` feature. Dedicated "transcription provider" setting —
OpenRouter has no `/audio/transcriptions`, so chat connection is not a safe
default; fail soft with clear error.

Composer: mic button in toolbar (Composer.tsx:578-598, Stop-button state
swap pattern at :632), `appendToMarkdown` on `TipTapHandle`
(TipTapEditor.tsx:99 — only `setMarkdown` exists today). PTT = turn
boundary: transcript lands in draft, user sends. Degraded-accent notice =

WER gate: vendor 5-10 Common Voice CC0 clips × 4-6 accents (few MB) +
Rust WER fn; `#[ignore]` IT behind env flag; thresholds recorded, above-threshold
accents drive the notice copy.

Out of V1: VAD/SmartTurn hands-free mode, smart-turn + silero models (v2),
voice clone, TTS.

Sizes: capture M (incl. permission spike) · transcribe-rs integration M ·

## Release mechanics

- Feature branches `feat/v0.4.0-*` per slice; merge to main via PR; release
  branch `release/v0.4.0` at the end.
- Version bump touches 4 files: `package.json`, `src-tauri/Cargo.toml`,
  `src-tauri/Cargo.lock`, `src-tauri/tauri.conf.json`.
- Release notes `docs/releases/v0.4.0.md` already exists as the scope spec —
  rewrite its sections into shipped-truth notes at release time (same as
  prior releases); update `docs/features.md` statuses and `docs/later.md`
  per slice as each lands.
- Tag `v0.4.0` → release.yml NSIS build.
- Pre-push gate each time: `fallow dead-code` (+ `fallow audit --base main`
  on branches), `ocr review -c <sha>`; CodeRabbit on the PR; `audit` +
  `review` subagents if CodeRabbit fails.
