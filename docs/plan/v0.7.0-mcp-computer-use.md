# Plan: 0.7.0 MCP setup UX and Windows computer use

Status: shipped with v0.7.0. Follow-up plan: `v0.8.0-hardening.md`. Owner: single maintainer.

Source: MCP and computer-use research provided on 2026-10-27, updated with the
local-navigator research on 2026-10-28. This is the execution plan for the
release. Verify protocol revisions, `rmcp` APIs, Windows UI Automation details,
the `jev` binary and crate versions before starting an item; the research itself
flags several unverified details.

## Scope decision (2026-10-29)

0.7.0 ships the MCP structured-config, secrets, import/export, bounded logs,
tool-hash review and Windows Job Object work, plus the computer-use
observe/action server with per-app tiers, hard denies, kill switch, overlay,
dry-run, action budget and audit. The protocol refresh (`server/discover`,
`Mcp-Method` / `Mcp-Name`, `ttlMs` / `cacheScope`), a Rust-owned state machine,
Form/JSON tabs, a details page, a composer server chip and typed error kinds move
to 0.8.0. Computer-use hardening and the scripted eval harness, publisher
verification and yield-to-user pause detection also move to 0.8.0. The optional
local navigator remains a gated 0.8.0 experiment.

## Release goal

0.7.0 makes MCP servers understandable and safe to operate, then uses that
foundation for a bundled Windows computer-use server. A user must be able to
import a normal MCP config, see why a server failed, approve the exact command,
inspect tools and logs, and trust that a changed tool definition needs review.
The agent must be able to observe and act in approved Windows apps with per-app
tiers, a kill switch, audit and interruptible actions.

This is an XL release. Ship one release, but split the work into separate PR
tracks. Build and dogfood the MCP manager first; the computer-use server is its
first bundled consumer.

## Baseline at 0.6.1

- MCP: stdio, Streamable HTTP, legacy `sse`, bearer tokens and OAuth 2.1 with
  DCR/PKCE/loopback. Tool approvals, deny rules, audit and namespacing exist.
- Gaps: the UI is a flat Name / Transport / Auth / Target form with no args,
  environment, headers, test-step log, server details or log drawer. There is no
  standard `mcpServers` import/export, no Job Object lifetime and no tool-hash
  re-approval.
- Windows stdio launch already resolves `npx`/`npm`/`pnpm`/`yarn`/`uvx` shims to
  `.cmd` files, builds PATH from the environment/registry/known tool directories,
  uses `CREATE_NO_WINDOW`, and allows 60 seconds for a cold install.
- Remaining Windows process work: Job Object with `KILL_ON_JOB_CLOSE`, bounded
  stderr logs, and refusing non-protocol stdout.
- Composer: images can be attached or dropped; raw clipboard image paste is
  already shipped.

## Workstream 0: AgentRouter OpenAI compatibility

This lands first because it is a user-visible provider failure, not an MCP
feature.

- Reproduce the Azure OpenAI "requested item was created under a different
  Azure OpenAI resource" 400 on AgentRouter GPT models that use `/v1/responses`.
- Remove cross-request item/resource affinity: send a stateless Responses
  request, do not reuse `previous_response_id` or stored item references across
  requests, and keep the full conversation in the current request.
- Do not replay `responses_items` for AgentRouter or other gateways. Rebuild the
  tool turn from the chat-shaped history so Azure-assigned item ids and
  encrypted reasoning never cross a multi-node pool. Keep `call_id` pairing.
- Retry once with an item-free body when a gateway still returns a
  cross-resource, decryption or "items are not persisted" error.
- Restore visible reasoning: send `reasoning.summary: "auto"` with the effort,
  keep `reasoning.encrypted_content` only for direct OpenAI replay, and preserve
  the existing summary/text delta parsing.
- Add regression tests for stateless request building, gateway item stripping,
  cross-resource classification, reasoning-summary requests and the AgentRouter
  fallback path.
- Record the final behavior in `docs/releases/v0.7.0.md` and `docs/features.md`.

Research result: the failure is not caused by `previous_response_id` (the app
does not use it). It is the replay of resource-bound item ids/ciphertext across
AgentRouter's Azure pool. The missing thinking is the absent
`reasoning.summary` opt-in.

## Workstream A: MCP foundation

**A1. Rust-owned state machine.** One manager per server with the states
`disabled`, `starting`, `ready`, `busy`, `needs_auth`, `needs_review`, `failed`,
`stopped`. The UI renders Rust state and sends intents only.

**A2. Structured config.** Replace the single `cmd` string with structured
fields: command, args, cwd, env, URL, headers, transport, auth and timeouts.
Accept the standard `mcpServers` JSON shape. Support import/export and
project-scoped servers. Keep approvals, tool policies and tool hashes in app
state, not in the portable file. Secrets stay behind `${secret:name}` references
in the Windows Credential Manager.

**A3. Windows process lifetime.** Put children in a Job Object with
`KILL_ON_JOB_CLOSE`. Drain stderr into a bounded per-server ring buffer and show
it in a log drawer. Refuse non-protocol stdout. Keep the current `.cmd` shim
resolution and Rust batch escaping; resolve the shim to its full path and spawn
it through Rust's `Command`, reject `& | < > ^ %` and quotes in arguments for
batch targets, and do not build a `cmd /c` string from config text.

**A4. Protocol refresh.** Probe `server/discover` first and fall back to the
legacy `initialize` handshake. Show the negotiated revision in server details.
Keep Streamable HTTP and legacy `sse`; the legacy transport is deprecated, not
removed, so do not add a new HTTP+SSE implementation or drop `sse` while target
servers still need it. Do not build Roots, Sampling or Logging. Send
`Mcp-Method` / `Mcp-Name` on Streamable HTTP and cache `tools/list` using
`ttlMs` / `cacheScope`.

**A5. Approval integrity.** Show the exact untruncated command before first run.
Hash tool definitions and move a server to `needs_review` when they change.
Treat annotations as hints, never as permission bypasses.

## Workstream B: MCP settings UX

- Server list with honest status pills and tool counts.
- Add/edit dialog with Form and JSON tabs plus a stepped Test connection.
- Server details with Tools, Logs, Config and About.
- In-chat tool-call and approval cards; composer server chip.
- Progressive disclosure: simple form first, then an Advanced section for
  protocol override, catalogue/execution timeouts, request headers, environment
  variables and an OAuth metadata URL.
- Default the protocol to Auto, not OpenCode's "Legacy (default)"; do not copy
  OpenCode's Code Mode control into MCP server config.
- Every failure maps to an error kind with a human message and a next action.

## Workstream C: computer-use MCP

0.7.0 ships tiers 1 and 3 only: Rust name/role matching and cloud escalation
with a pruned tree. The optional local verifier is 0.8.0 work; do not put it in
0.7.0.

- Ship a separate Rust `computer-use` stdio MCP server, bundled with the app and
  spawned by the MCP manager. It must not run as an elevated process.
- Observation tools: `list_apps`, `list_windows`, `get_state` (compact UIA tree,
  optional screenshot) and `screenshot`. Use UI Automation first and pixels only
  as a fallback for canvas/Chromium/Electron apps.
- Action tools: `invoke`, `click`, `type_text`, `set_value`, `press_keys`,
  `scroll`, `drag`, `wait`, `focus_window`, `launch_app`, and gated clipboard
  tools. No raw shell tool in the computer-use server.
- Element ids are snapshot-scoped; stale ids return `stale_snapshot` and ask the
  model to observe again. Cap nodes/depth and keep coordinates in physical
  pixels with per-monitor DPI awareness v2.
- Per-app approval keyed by executable path and publisher signature, with
  `View` / `Interact` / `Full` tiers. Hard denies for terminals, password
  managers, UAC/secure desktop, security tools and password fields.
- Kill switch, always-on-top control indicator, pause when the user takes over,
  action budgets, dry-run mode, before/after audit thumbnails, and confirmation
  for irreversible actions.
- Settings: Computer use page with master toggle (off by default), app allowlist
  and tiers, hard-deny list, hotkey picker, overlay toggle and audit viewer;
  in-chat approval and run panel.
- Build an eval set of about twenty Windows tasks (Notepad, Explorer, Settings,
  a Chromium form, a WinUI dialog, a long list, a modal) and record success,
  steps, tokens and wrong clicks.
- **Internal gate:** do not expose action tools until the observe eval passes on
  Notepad, Explorer, Settings, a Chromium app and a WinUI app. If 0.7.0 runs out
  of time, ship observe-only and hold actions to 0.7.1; never weaken the safety
  gates to hit the version.

## PR slices

1. **Provider fix:** AgentRouter Responses statelessness and reasoning parts.
2. **MCP config/state foundation:** structured config, migration, state machine,
   Job Object, logs, import/export.
3. **MCP settings UX:** list, add/edit Form/JSON, details, test steps, errors.
4. **Computer-use server:** observation tools and eval harness.
5. **Computer-use safety:** action tools, per-app tiers, kill switch, audit.
6. **Integration:** settings, approvals, docs, release gate.

Each slice must keep the app runnable and the existing MCP paths working. Do not
drop legacy `sse` or OAuth while the new manager is being built.

## Acceptance gates

- A standard `mcpServers` file imports, runs and exports without losing secrets
  or app-only policy.
- A failed server shows a human error, the failing step and a next action.
- A changed tool definition moves the server to `needs_review`.
- Closing the app leaves no child process behind.
- The observe eval passes before action tools are exposed.
- Action tools refuse hard-denied apps and secure-desktop input.
- The kill switch interrupts an in-flight action.
- The full local gate is green.

## Non-goals and deferred

- No macOS/Linux branches; this remains Windows-only.
- No elevated agent, no background input into the secure desktop, no raw shell
  in the computer-use server, and no remote steering in the first version.
- No local screenshot/vision model on the target laptop; cloud vision only.
- No custom-scheme OAuth callback, pre-registered OAuth clients or server-side
  token revocation in this plan; those remain MCP follow-ups.
- Full stateless MCP 2026-07-28 support depends on `rmcp` and on real servers.
  Probe and negotiate first; do not drop the legacy path while target servers
  still need it.

## After 0.7.0

Execution plan: `docs/plan/v0.8.0-hardening.md`.

### 0.8.0 — hardening, eval and optional local navigator

- Re-run the MCP and computer-use eval sets on a clean Windows machine; fix lazy
  Chromium trees, DPI/multi-monitor errors, elevated-window and secure-desktop
  errors, stale snapshots and orphan processes.
- Finish the audit viewer, dry-run polish, action budgets, installer checks and
  documentation.
- Do not start a new protocol experiment in this release.
- Optional local navigator (tier 2), only after the 0.7.0 eval passes.
  `jevos-v5` via `jev.exe` (OpenVINO INT8) is a yes/no verifier, not a chooser:
  ask one question per top candidate, act only if the calibrated best is
  `>= 0.80` and the runner-up is `< 0.50`; otherwise escalate to tier 3. Spawn
  it like an MCP sidecar with `CREATE_NO_WINDOW`, a Job Object, a random
  localhost port and API key, idle stop and below-normal priority. Start in
  shadow mode for 1-2 weeks. Keep it off by default; tiers 1 and 3 must still
  work without it.
- Local navigator gates: p50 `<= 3 s` plugged in / `<= 5 s` on battery,
  `>= 90%` top-1 on calibrated `p >= 0.80`, and `>= 60%` of steps finished
  without the cloud. Use `q8_0` by default; `q4_k_m` only if it agrees with
  `q8_0` on `>= 98%` of steps. If the gates fail, ship without tier 2.
- Local navigator UI: Settings -> Computer use -> Local navigator toggle, status
  pill, disk size, delete model, run benchmark, and audit columns (step,
  candidates, probabilities, tier, ms). No local vision model; the cloud handles
  screenshots.

### 1.0.0 — polish and integration

- Integrate computer use into the MCP settings and approval surfaces; finish
  documentation, installer checks and a security review.
- Re-run the MCP and computer-use eval sets on a clean Windows machine.
- If the local navigator passed the 0.8.0 gates, ship it; otherwise omit it.
- Do not start a new protocol experiment in this release. If 0.7.0/0.8.0 slip,
  ship 1.0.0 with the MCP UX and move computer use to v2 rather than weakening
  the safety gates.
