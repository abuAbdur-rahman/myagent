## Locked decisions
1. Downscale: max side 1568px, JPEG q0.80, PNG→JPEG unless alpha needed, skip if smaller, cap ~2MB/image. Reason: OpenAI `detail:low` 512px budget / `high` 2048px practice; OpenWebUI canvas-resize pattern; 1568 middle ground.
2. Wire format: OpenAI content parts `[{type:text},{type:image_url,image_url:{url}}]`, url = data-URL or https. Reason: OpenAI-compatible standard; opencode `openai-chat.ts:128` same shape.
3. Gating: `capabilities.input` prefix-`image` style flag plumbed from `/models` → `ModelCaps` → picker; non-vision submit → drop part + toast (OpenWebUI `Chat.svelte:3343` pattern). Reason: F4 Done criterion is gating, not just transport.
4. Resize in renderer (canvas, aspect-preserve, OpenWebUI `compressImage` pattern). Reason: zero Rust image deps, Windows-only stays lean.
5. Budget: 25MiB trigger / 15MiB target per turn with `IMAGE_REMOVED` placeholder notice (opencode `model-request.ts:43` pattern). Reason: prevents silent context blowout.
6. Scope: PNG/JPEG/GIF/WebP only. No HEIC convert, no PDF-as-image in v1. Reason: Pillow-verify allowlist (`validate.py:35`) equivalent minimal set.
