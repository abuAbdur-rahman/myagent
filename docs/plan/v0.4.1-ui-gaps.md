### DSML wire format (implementation reference)

The ASCII spelling, which is the easiest to test against:

```text
<|DSML|tool_calls>
<|DSML|invoke name="get_weather">
<|DSML|parameter name="location" string="true">Paris</|DSML|parameter>
</|DSML|invoke>
</|DSML|tool_calls>
```

Newer models ship the same tags with U+FF5C FULLWIDTH VERTICAL LINE
(`｜`) instead of the ASCII pipe, and some hosts double that bar. The byte
form is not stable across upstreams, so the scanner accepts all three
spellings and never rewrites history into a different one.

Semantics that matter:

- One `tool_calls` wrapper holds one or more `invoke` blocks. Whitespace
  between tags is insignificant.
- `string` defaults to true: the value is a raw string, not XML-decoded.
  Only `string="false"` means "parse this as JSON", so numbers and objects
  arrive typed.
- The V3.1 and R1 series use a different envelope (`tool_calls_begin` /
  `tool_call_begin` / `tool_sep` special tokens with `name` then raw JSON).
  That form is not what the reported symptom shows, but a complete scanner
  handles both; T1a covers V4 DSML first and V3.1 second.

Failure modes seen in the wild:

- Markup **instead of** `tool_calls` — the agent treats it as final text and
  skips execution entirely.
- Markup **in addition to** `tool_calls` — naive parsing runs the call twice.
- Orphan closers left in stored history after one bad turn, which teach the
  model to keep emitting XML and poison later turns.
- R1-era variants: a `json` fence prefix leaking into arguments, and
  `tool_choice=none` leaking raw tokens because no parser was initialised.

### U9 — session panel (the right-hand block) — 17 h

The prototype's `Progress` block is one 344 px dock with three sections
(steps, Outputs, Used in this session). Nothing in the app is equivalent:

(`ArtifactsPanel.tsx:90`), the trigger is disabled when `panelArtifact` is

- **Steps** — `todos` per chat (`db.listTodos`), already ordered by `position`.

**Verified before writing:** Ollama's OpenAI-compatible base is
`https://ollama.com/v1` for cloud and `http://localhost:11434/v1` for local;
cloud requires `Authorization: Bearer`, local ignores the key
(`docs.ollama.com/api/introduction`, `.../authentication`). Alternatives
return 404. DeepSeek's direct base is `https://api.deepseek.com/v1`.

**Provider caveats to honour:**

- Ollama Cloud's `/v1` is a documented *subset*: no stateful Responses, no
  built-in web search through the API, no custom/freeform tool-call replay.
  The app's `web_search` tool is executed by Rust, so it still works; the
  replay path in branch handling does not. Test a branched chat on cloud.
- DeepSeek direct has no `reasoning_effort`; the reasoner thinks by default.
  A test must assert the field is absent, not merely ignored.
- `wants_stream_usage` (`llm.rs:396`) is true for every kind except
  Agent Router. If either new endpoint rejects `stream_options`, gate it by
  kind rather than dropping usage everywhere.

### Phase D — started

**P0 shipped early (pulled out of Part 3)** — `ProviderKind` grows to six: OpenRouter, Agent Router, DeepSeek, Ollama Cloud, Ollama (local) and Custom, each with a default base URL, a label and a keyless flag. Local Ollama asks for no key anywhere (onboarding, dialog, pill), because a localhost server ignores one. `lookupSupportsTools` now treats every known kind except Custom as tool-capable, since a hosted endpoint that lists no capability data otherwise loses its tools. In Rust the effort field became a two-step decision: `provider_takes_effort` refuses `deepseek`, `ollama` and `ollama-cloud`, and a new `attach_effort` writes either the gateway `reasoning` block or the OpenAI `reasoning_effort`. Tests assert the deepseek body carries neither key, and that Ollama streams without `stream_options`.

**S8 shipped** — the Providers page answers "is this key even usable?" in one pill: No key, Untested, Connected, Key unreadable, or No key needed. `api_key_hint` returns a mask computed in Rust (`mask_key` moved to `pub(crate)` so the search page and this page share one rule); the key itself still never reaches the renderer. Migration 24 adds `connections.key_tested_at`, so "Untested" survives a restart instead of being a session illusion, and a passing Test stamps it. The card shows the mask, when it was last tested and the test's own result strip (models found, or the classified provider error) instead of a toast that disappears. Rotating a key is the same Edit dialog; removing one is its own button, behind a confirm that says sending will fail.

**S6 shipped** — the Models page gained a capability table for one provider at a time, because rendering every model of every provider at once is several hundred rows nobody reads. Each row shows the context window, the tool decision the runtime will actually make, a vision state and two controls: force vision on/off (Auto keeps the catalog answer) and hide from the picker. `lib/model-table.ts` keeps the mapping testable, and its tests pin the honesty rule: a window or modality the provider never reported reads Unknown, never a guess, while an explicit override wins over the catalog. `collectModelOptions` now lists keyless providers too, so a local Ollama connection is not skipped for lacking a key it never needed. Per-model parameters stay out, as decided.

**S9 shipped** — a standing-instructions editor on General (saved explicitly, with a character count and a Clear), sent with every chat, plus a per-chat override in the chat's ••• menu. Migration 25 adds `conversations.system_prompt`; the prompt chain is now identity → standing → durable memory → project (with its instructions and memory) → this chat, and `context-prompt.test.ts` asserts that order, that blank prompts add no heading, and that the 6000-character cap still holds. The context bar got the toggle the plan asked for; off means the row disappears rather than showing an empty strip.

**S10 shipped** — Appearance gained a text-size slider (0.9–1.2, applied as a root font scale so rem-based text and spacing grow together instead of clipping), a density choice (comfortable/compact, driven by two CSS variables for the sidebar row height and message gap) and the date-grouping switch, which the sidebar now honours through `arrangeChats` — pinned chats still float above a flat "Chats" list when dates are off. Parsing lives in `lib/appearance.ts` and is tested against missing, corrupted and out-of-range values, because a bad preference must fall back to the default rather than shrink the UI to nothing.

**U13 shipped** — `remember` proposes instead of writing. Migration 22 adds `pending_memories`, the tool inserts there and answers "Queued for the user to review", and the tool description tells the model not to claim a save. A turn that proposed something raises a toast with Review, which opens the Memory page. `approvePendingMemory` copies the row into `memories` with the same id before deleting it from the queue, so a retry cannot duplicate; Undo on the toast reverses exactly that step. The Memory page lists the queue with kind, scope, source chat and age, and Save/Dismiss per row. Nothing enters the prompt before approval, which is the E6 promise, and the secret check E2 still runs on the same content it always did.

**S5 shipped (scope switcher deferred)** — the Memory page now searches notes by text, kind or scope, shows "3 of 12" when a filter is on, and gives every saved note a meta line: scope, where it came from, and how long ago. Migration 23 adds `source_conversation_id` to `memories` so an approved note keeps the chat it came from rather than turning into an anonymous row; a note the user typed says "Added by you". Export copies or downloads one JSON file with both `saved` and `pending`, because an export that silently drops queued drafts is a lie. `lib/memory-export.ts` holds the filter and the file shape, and `context-memory.test.ts` pins the E1 promise: global notes travel with every chat, project notes only with their own project.

Deferred on purpose:

- **Global/project switcher on this page**: project memory already has an editor inside the project dialog and the project header. A second editor for the same rows needs a decision about which surface owns them, not another switcher. Until then the page is what its old copy claimed: global memory.

### Phase E — started

**U6 shipped** — the sidebar gained a filter that offers All chats, Pinned and every project by name, applied after the tag filter so the two compose. `lib/chat-filter.ts` keeps the parsing, matching and empty-state copy pure and tested, because a filter that silently shows the wrong chats is worse than no filter. A filtered empty list says what it was looking for ("No chats in Agent yet.") and offers Show all chats instead of the bare "No chats yet." that reads like data loss. Projects and New project hide while a project filter is active, since the list beneath already answers that question.

**U3 shipped** — pasting a code block into the composer now inserts a real code-block node with a guessed language, so the fence survives editing instead of arriving as run-on text. `fenceForPaste` only wraps when the text clears a code score (indentation, braces, semicolons, keywords), so a pasted paragraph or markdown list is left exactly as it was, and an already fenced block is never fenced twice. Undo restores the raw paste at the same position rather than deleting the paste, which is what "restore the raw paste" has to mean.

**U15 shipped** — attachments render as a 168 px card: type chip read from the mime type (not the extension), a name that wraps to two lines, and a meta line built from the size and character count that says "Size unknown" rather than inventing one. `docCard` is a pure, tested mapping, and the card reads only the JSON stored on the message, so it looks the same after a reload.

**U9e shipped** — a tool's search domains and written files are now stored on its log entry. `llm.rs` extracts hosts from `web_search` output and the path from `sandbox_write`/`sandbox_edit` arguments, and sends them in a `tool_sources` event that the store merges onto the entry by id; a separate event was chosen over widening all twelve `tool_result` emissions for a value only two tools produce. **U9a–d shipped** — the right dock is no longer an artifact viewer that exists only while an artifact is open. `panelView` sits beside `panelOpen`: the header trigger is enabled with nothing to show and opens Progress, opening an artifact switches the view, and the artifact header's Back arrow returns. Progress shows steps in position order with a distinct icon per status, Outputs (artifacts newest first, deduped on title + language, first two as cards, the rest and every written file as rows) and Used in this session (upload names, image count, distinct tool names with `+n`, and the search domains from U9e). `lib/session.ts` holds the three mappings and is tested against duplicate artifacts, repeated writes, empty transcripts and step counts.

**U2 shipped** — the header shows `Step 3 of 5` from the same todo list the panel renders and opens Progress on click. `TodoChecklist.tsx` and its composer render are gone: keeping both would show one list twice and leave a component with no consumer.

**U10 shipped** — a sidebar Outputs entry opens a gallery of the current chat's artifacts and written files, reusing the same `ArtifactThumb` the panel uses. Two deviations, both deliberate:

- **Written files are rows, not buttons.** The log stores the path but not the content, so opening one would show an empty artifact view. The row is informative until a file-content source exists.
- **Domains travel in `tool_sources`, not on `tool_result`.** Same stored shape, one emission instead of twelve.

## Open risks

- U9 and U10 share the thumbnail component. Extract it in U9c and have U10
  import it; two iframes with different `sandbox` flags in one app is how the
  `allow-scripts` preview survives a security review.
- U9's Outputs rows and web row are only as complete as U9e. Without the two
  tool-entry fields the block shows artifact cards and a search count, nothing
  more. Deriving them from `preview` or `summary` is string scraping, not data.
- U16 must land after S2, because the fallback chain reads the per-key
  quota state S2 creates.
- New primitives in S0 touch every settings page: land S0 alone, then page
  by page, so a review never mixes shell churn with page logic.
- DSML: clean the text that gets **stored**, not only what gets rendered.
  One orphan `invoke` closer left in history teaches the model to keep
  emitting XML, which is the poisoning failure mode in Part 0.
- Do not XML-decode parameter values: the model sends raw text, so decoding
  turns `&amp;` in a shell command into `&`.
- If `content` markup and `tool_calls` both arrive, dedupe on name plus
  arguments before running anything, and never synthesize a call from an
  unclosed envelope at end of stream.
- T2's fallback table must cite its numbers. A guessed context size moves
  the auto-compact threshold (`store.tsx:1554`) without anyone noticing.
- This is a bridge release, not a polish pass: 220 h across providers, a
  settings rebuild and a stream parser. If it has to ship smaller, keep
  Phase 0 and A–C and defer D, E, F; that is still a coherent release.
