## Locked decisions
1. Layout: `skills/<name>/SKILL.md` + optional `scripts/`, `reference/`; index only `name` + `description`, lazy full-read on trigger. Reason: opencode `skill.ts:55-68` lazy-load + sibling-sample-cap-10 pattern.
2. Two triggers only: model calls `skill(id)` agentic tool, or explicit user `@skill` attachment. Reason: opencode `skill.ts:10` tool + `prompt.ts:56-76` `@skill` resolution; no boot discovery (`instance.ts:127`).
3. Injection wraps as delimited block with base-dir line (`toModelOutput:36-53` pattern), user-role content before user text (`to-llm-message.ts:271`). Reason: traceable, compaction-safe (`compaction.ts:761-763` keeps `[Skill activated:name]+text`).
4. Permission: catalog pre-filtered by deny (`available:33-34` pattern); `skill` tool asserts per-id (`skill.ts:51-58`, action=`skill`, resources=`[skill.id]`). Reason: skills obey same engine as tools.
5. Direct user `@mention` activation bypasses approval; model-initiated `skill()` call goes through permission assert (Ask default). Reason: user intent is explicit; model intent needs oversight (answers opencode scout open Q7).
6. No slash-command behavior for skills (opencode v2 removed `slash` flag). File commands are J9. Reason: avoid two dispatch paths.
