# Plan: MCP setup UX, Windows computer use and optional local navigator (0.7.0 → 1.0.0)

Source: MCP and computer-use research provided on 2026-10-27, updated with the
local-navigator research on 2026-10-28. This is a scheduling document. Verify
protocol revisions, `rmcp` APIs, the `jev` Windows binary, the `/v1/systemone`
shape and crate versions before starting an item; the research itself flags
several unverified details.

## Current state (0.6.1)

- MCP: stdio, Streamable HTTP, legacy `sse`, bearer tokens and OAuth 2.1 with
  DCR/PKCE/loopback. Tool approvals, deny rules, audit and namespacing exist.
- Gaps: the UI is still a flat Name / Transport / Auth / Target form with no
  args, environment, headers, test-step log, server details or log drawer. There
  is no standard `mcpServers` import/export, no Job Object lifetime and no
  tool-hash re-approval.
- 0.6.1 fixes the Windows stdio launch path: `npx`/`npm`/`pnpm`/`yarn`/`uvx`
  shims resolve to `.cmd` files and Rust's standard library handles batch
  escaping, PATH is built from the current environment, the registry and known
  tool directories, children use `CREATE_NO_WINDOW`, and a cold `npx` install
  gets 60 seconds instead of 20.
- Remaining Windows process work: put children in a Job Object with
  `KILL_ON_JOB_CLOSE`, drain stderr into a bounded per-server log, and refuse
  non-protocol stdout.
- Composer: images can be attached or dropped; 0.6.1 adds raw clipboard image
  paste for screenshots that arrive as clipboard items rather than files.

## Release mapping

### 0.7.0 — MCP setup UX and Windows computer use (XL)

This release has two tracks. They share the MCP manager, approval gate and
settings surface, so build the manager first and dogfood it with the bundled
computer-use server. It is XL: split the work into two PR tracks, but ship one
release and keep the observe gate before actions.

**Track A: MCP setup and safety UX**

- **Rust owns the state machine.** One manager per server with the states
  `disabled`, `starting`, `ready`, `busy`, `needs_auth`, `needs_review`,
  `failed`, `stopped`. The UI renders Rust state and sends intents only.
- **Portable config.** Accept the standard `mcpServers` JSON shape; support
  import/export and project-scoped servers. Keep approvals, tool policies and
  tool hashes in app state, not in the portable file. Secrets stay behind
  `${secret:name}` references in the Windows Credential Manager.
- **Windows process lifetime.** Put children in a Job Object with
  `KILL_ON_JOB_CLOSE`, treat stderr as logs while refusing non-protocol stdout,
  and add a per-server log drawer. Keep the current `.cmd` shim resolution and
  Rust batch escaping from 0.6.1; resolve the shim to its full path and spawn
  it through Rust's `Command`, reject `& | < > ^ %` and quotes in arguments for
  batch targets, and do not build a `cmd /c` string from config text.
- **Protocol refresh.** Probe `server/discover` first and fall back to the
  legacy `initialize` handshake. Show the negotiated revision in server
  details. Keep the existing Streamable HTTP and legacy `sse` paths; the legacy
  transport is deprecated, not removed, so do not add a new HTTP+SSE
  implementation or drop `sse` while target servers still need it. Do not
  build Roots, Sampling or Logging; elicitation uses multi round-trip
  requests. Send `Mcp-Method` / `Mcp-Name` on Streamable HTTP and cache
  `tools/list` using `ttlMs` / `cacheScope`.
- **Settings UI.** Server list with honest status pills and tool counts; add/edit
  dialog with Form and JSON tabs plus a stepped Test connection; server details
  with Tools, Logs, Config and About; in-chat tool-call and approval cards; a
  composer server chip. Use progressive disclosure: the simple form first, then
  an Advanced section for protocol override, catalogue/execution timeouts,
  request headers, environment variables and an OAuth metadata URL. Default the
  protocol to Auto, not OpenCode's "Legacy (default)"; do not copy OpenCode's
  Code Mode control into MCP server config. Every failure maps to an error kind
  with a human message and a next action.
- **Approval integrity.** Show the exact untruncated command before first run.
  Hash tool definitions and move a server to `needs_review` when they change.
  Treat annotations as hints, never as permission bypasses.
- **Tests.** Config validation, state transitions, tool-hash changes,
  orphan-process check on app exit, and the failure drills in the research.
  Command normalization and PATH building are covered by the 0.6.1 tests.

**Track B: computer-use MCP**

- 0.7.0 ships tiers 1 and 3 only: Rust name/role matching and cloud escalation
  with a pruned tree. The optional local verifier is 0.8.0 work; do not put it
  in 0.7.0.
- Ship a separate Rust `computer-use` stdio MCP server, bundled with the app and
  spawned by the MCP manager. It must not run as an elevated process.
- Observation tools: `list_apps`, `list_windows`, `get_state` (compact UIA tree,
  optional screenshot) and `screenshot`. Use UI Automation first and pixels only
  as a fallback for canvas/Chromium/Electron apps.
- Action tools: `invoke`, `click`, `type_text`, `set_value`, `press_keys`,
  `scroll`, `drag`, `wait`, `focus_window`, `launch_app`, and gated clipboard
  tools. No raw shell tool in the computer-use server.
- Element ids are snapshot-scoped; stale ids return `stale_snapshot` and ask the
  model to observe again. Cap nodes/depth and keep coordinates in physical
  pixels with per-monitor DPI awareness v2.
- Per-app approval keyed by executable path and publisher signature, with
  `View` / `Interact` / `Full` tiers. Hard denies for terminals, password
  managers, UAC/secure desktop, security tools and password fields.
- Kill switch, always-on-top control indicator, pause when the user takes over,
  action budgets, dry-run mode, before/after audit thumbnails, and confirmation
  for irreversible actions.
- Settings: Computer use page with master toggle (off by default), app allowlist
  and tiers, hard-deny list, hotkey picker, overlay toggle and audit viewer;
  in-chat approval and run panel.
- Build an eval set of about twenty Windows tasks (Notepad, Explorer, Settings,
  a Chromium form, a WinUI dialog, a long list, a modal) and record success,
  steps, tokens and wrong clicks.
- **Internal gate:** do not expose action tools until the observe eval passes on
  Notepad, Explorer, Settings, a Chromium app and a WinUI app. If 0.7.0 runs out
  of time, ship observe-only and hold actions to 0.7.1; never weaken the safety
  gates to hit the version.

Exit: a user can import a standard MCP config, see why a server failed, approve
the exact command, inspect its tools and logs, and trust that a changed tool
definition requires review; the agent can observe and act in approved Windows
apps with per-app tiers, a kill switch, audit and interruptible actions.

### 0.8.0 — Hardening, eval and optional local navigator (L)

- Re-run the MCP and computer-use eval sets on a clean Windows machine; fix lazy
  Chromium trees, DPI/multi-monitor errors, elevated-window and secure-desktop
  errors, stale snapshots and orphan processes.
- Finish the audit viewer, dry-run polish, action budgets, installer checks and
  documentation.
- Do not start a new protocol experiment in this release.
- **Optional local navigator (tier 2).** Only after the 0.7.0 eval passes.
  `jevos-v5` via `jev.exe` (OpenVINO INT8) is a yes/no verifier, not a chooser:
  ask one question per top candidate, act only if the calibrated best is
  `>= 0.80` and the runner-up is `< 0.50`; otherwise escalate to tier 3. Spawn
  it like an MCP sidecar with `CREATE_NO_WINDOW`, a Job Object, a random
  localhost port and API key, idle stop and below-normal priority. Start in
  shadow mode for 1-2 weeks. Keep it off by default; tiers 1 and 3 must still
  work without it.
- **Local navigator gates.** Benchmark plugged in and on battery: p50 `<= 3 s`
  plugged in / `<= 5 s` on battery, `>= 90%` top-1 on calibrated
  `p >= 0.80`, and `>= 60%` of steps finished without the cloud. Use `q8_0` by
  default; `q4_k_m` only if it agrees with `q8_0` on `>= 98%` of steps. If the
  gates fail, ship without tier 2.
- **Local navigator UI.** Settings -> Computer use -> Local navigator toggle,
  status pill, disk size, delete model, run benchmark, and audit columns (step,
  candidates, probabilities, tier, ms). No local vision model; the cloud
  handles screenshots.

Exit: eval pass, no orphan processes, a clean security review, and a local
navigator that is either proven by the gates or absent.

### 1.0.0 — Polish and integration (M)

- Integrate computer use into the MCP settings and approval surfaces; finish
  documentation, installer checks and a security review.
- Re-run the MCP and computer-use eval sets on a clean Windows machine.
- If the local navigator passed the 0.8.0 gates, ship it; otherwise omit it.
- Do not start a new protocol experiment in this release. If 0.7.0/0.8.0 slip,
  ship 1.0.0 with the MCP UX and move computer use to v2 rather than weakening
  the safety gates.

## Non-goals and deferred

- No macOS/Linux branches; this remains Windows-only.
- No elevated agent, no background input into the secure desktop, no raw shell
  in the computer-use server, and no remote steering in the first version.
- No local screenshot/vision model on the target laptop; cloud vision only.
- No custom-scheme OAuth callback, pre-registered OAuth clients or server-side
  token revocation in this plan; those remain MCP follow-ups.
- Full stateless MCP 2026-07-28 support depends on `rmcp` and on real servers.
  Probe and negotiate first; do not drop the legacy path while target servers
  still need it.

## Order

1. 0.7.0 MCP manager, setup UX and Windows spawn correctness.
2. 0.7.0 computer-use server: observe first, then actions and safety.
3. 0.8.0 hardening, eval and optional local navigator.
4. 1.0.0 integration, eval and security review.
