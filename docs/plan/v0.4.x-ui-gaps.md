# v0.4.x — UI gaps and Settings rebuild

Compares the design prototype (single-file mockup, attached to the review
thread, **not** in this repo) against the app as of **v0.3.6**. Every
"today" cell was read in code, not taken from the docs.

Scope of this file: the prototype's net-new surface plus a rebuild of most
Settings pages. Placeholder-only prototype chrome (titlebar buttons,
download/export buttons with no handler) is excluded — there is no
behaviour to port.

**Owner decisions taken here:**

| Question | Decision |
| --- | --- |
| Models page depth | Capability table only. Per-model parameters (temperature, max tokens, top-p) stay out — they need a request-body change in Rust plus tests. |
| Settings surface | Keeps the modal dialog (`min(960px, 92vw)` × `min(640px, 86vh)`, `SettingsDialog.tsx:88`). No routed page, no layout change in `App.tsx`. |
| Plan of record | This file. Hours are ideal dev hours, excluding the two review gates. |

Hours are ideal work: UI, Rust where needed, and the test each row's
Done line asks for. Rule 5 of `later.md` applies — two rows below are **L**
and must be split before they start.

## Open risks

- Part 1's U9 (session panel) and U10 (outputs) share data. Build U9 first
  or the gallery gets rewritten twice.
- U16 must land after S2, because the fallback chain reads the per-key
  quota state S2 creates.
- New primitives in S0 touch every settings page: land S0 alone, then page
  by page, so a review never mixes shell churn with page logic.
