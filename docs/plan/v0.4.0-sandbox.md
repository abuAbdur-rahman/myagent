# v0.4.0 S1 — Sandbox plan (opt-in, foolproof)

Implements `docs/releases/v0.4.0.md` S1. Owner answers locked in;
implementer fills runtime choice.

## Locked decisions (owner)
1. Runtime: docker or lighter linux, ubuntu/debian choice. No internet
   ever (`--network none` or equivalent). Reason: foolproof > fast.
2. Off by default. Settings: enable + distro + predownloaded packages
   (python/node/rg/sed/grep baseline). Reason: explicit consent +
   no surprise downloads.
3. Tool floor: python/node create/edit/delete files, run code, rg/sed/
   grep/glob. Implementer may swap better tools with reason. Reason:
   small-task autonomy without accept-fatigue.
4. Decision model (M1, ships first) pre-screens dangerous commands
   before exec. Reason: machine judgment replaces blanket prompts.
5. Every exec audit-logged (J8 writer). Reason: traceability.

## Runtime options (implementer picks, in order)
1. Docker Desktop (WSL2 backend) + `docker run --network none
   --memory --cpus --read-only + project-dir bind (rw)`.
   Proven, heaviest dep. Detect absence → guide install, block enable.
2. WSL2 direct (`wsl --import` ubuntu/debian tar, `.wslconfig`
   lockdown). Native, no Docker dep. VERIFY net-off + bind story.
3. Fallback: refuse enable with reason. Never host-exec as "sandbox".

Pick 1 unless 2 verifies clean on EliteBook-class hardware.
Windows-only; no macOS/Linux branches.

## Isolation contract
- Net: none. egress = 0 (prove with test: `curl`/`ping` fail).
- FS: exactly one bind — project dir. No home, no vault, no DB.
- Secrets: never env-passed. BYOK keys stay host-side; sandbox
  code needing a key calls back via host tool (permission-gated).
- Caps: `--memory 2g --cpus 2` defaults, tunable in Settings.
- Pwn containment: non-root user, `--read-only` rootfs + rw only
  on the bind + tmpfs /tmp. VERIFY flags on chosen runtime.

## Tauri wiring
- New `src-tauri/src/sandbox.rs`: `sandbox_status`,
  `sandbox_enable(distro, packages)`, `sandbox_exec(cmd, cwd, timeout)`
  streaming `SandboxEvent{stdout,stderr,exit}` over existing
  Channel pattern (`api.ts` `chatStream` analog), cancel via
  `cancel.notified()` reuse.
- Settings UI: enable toggle + distro picker + package list +
  caps + exec log viewer (extends Settings modal pattern).
- Tool specs: `sandbox_read/write/edit/delete/run` in `tools.rs`
  shape; `approval_resources` returns sandbox path/cmd; inside
  sandbox mode check() auto-allows ONLY sandbox-scoped calls after
  M1 screen passes — host calls still Ask.

## Permission mapping
- Toggle ON = permission mode "sandbox" (Claude-Code-modes analog).
- Pre-exec: M1 injection screen scores cmd; destructive pattern
  (rm -rf /, mkfs, fork-bomb, outbound socket) → Ask/block even
  inside sandbox. Fail-closed on screen error.
- Post-exec: `log_audit` row per exec (tool, cmd-trunc, exit).

## File sync
- Bind mount = live. Host watches change events to refresh UI
  (reuse notify-once pattern or poll; VERIFY cheapest).
- Undo/diff: v2 remainder (NOT in 0.4.0). Sandbox edits are final;
  say so in Settings copy.

## Tests (Prove-It)
- cargo: no-net (egress fails), bind-escape fails (`/etc/passwd`,
  `..` jail), caps enforced, screen-blocks-dangerous, audit row
  per exec, fail-closed when daemon down.
- vitest: toggle persists, distro picker lists, exec log renders,
  dangerous cmd surfaces Ask card.

## Gate
`npx tsc --noEmit`, `cargo fmt --check`,
`cargo clippy --all-targets -- -D warnings`, `cargo test`,
`fallow dead-code`, vitest. + manual: 10-min exec soak, no host
leak (proc/net/fs audit).
