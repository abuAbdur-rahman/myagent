# v0.5.1 — Responses API fallback for OpenAI-compatible providers (patch)

> Fixes the AgentRouter failure where every GPT model it still serves rejects
> `/v1/chat/completions` with `400 … does not support /v1/chat/completions, use
> /v1/responses`. 0.5.1 keeps the existing chat feature working by adding a
> Responses adapter behind the same stream, tool loop, titles and summaries.
> No schema change, no new setting, no memory change.

---

## 1. Why a patch

0.5.0 shipped chat, tools and titles against the Chat Completions shape. That is
still correct for OpenRouter, DeepSeek, Ollama and most custom gateways. It is
wrong for AgentRouter's current catalogue:

- `gpt-5.6-sol`
- `gpt-6-astra`
- `gpt-6.1-sol`

All three return:

```
400 Bad Request: … does not support /v1/chat/completions, use /v1/responses
```

The user cannot chat, call tools, or generate a title with those models. This is
a compatibility fix for an already-released feature, so it is a patch, not a
minor. MCP authorization remains 0.6.0.

No SQL migration, no data move, no settings page, no MCP change.

---

## 2. Scope

| In 0.5.1 | Out |
| --- | --- |
| Auto-detect the `/v1/responses` marker on any chat request | A per-connection "API mode" setting |
| Responses request body: `input`, flat tools, `store:false` | `previous_response_id` or stored responses |
| Responses SSE: text, reasoning summaries, function calls, usage, finish | Built-in OpenAI tools (web search, file search, computer use) |
| Tool loop with `function_call_output` and replay of raw output items | New tools or MCP changes |
| Non-stream Responses for `complete_text`, `summarize`, `suggest_title` | Changing the prompt or title rules |
| One in-memory marker per `base_url|model` | Persisting the marker in SQLite |
| Fixtures + unit tests for the adapter | A live AgentRouter integration test in CI |

## 3. Detection

A single failed Chat Completions request is the probe. The marker is accepted
when the upstream error mentions `chat/completions`, `responses`, and either
`does not support`, `not supported`, or `use /v1/responses`.

```text
key = base_url.trim_end('/') + "|" + model
```

The key is stored in a process-wide `HashSet`. The first request for a model
pays one extra 400; later requests go straight to `/responses`. The set is
intentionally not persistent:

- a restart re-probes once, which is cheap and avoids a stale marker if a
  gateway changes its catalogue;
- no new column, no migration, no user-visible state.

Only a 400 with the marker triggers the retry. A 401, 403, 429, 5xx, network
error, content block or validation error keeps its current handling. The retry
is attempted only when no bytes have been streamed, so the UI never sees a
partial answer followed by a second answer.

## 4. Request mapping

Chat Completions history stays the internal format. The adapter converts at the
HTTP boundary, so the agent loop, permissions, audit rows and tool runner do not
change.

| Chat Completions | Responses |
| --- | --- |
| `messages[]` | `input[]` |
| `system` / `user` string | `{ role, content }` |
| user `text` parts | `input_text` |
| user `image_url` parts | `input_image` with `image_url` string and optional `detail` |
| assistant `content` | `{ role:"assistant", content }` |
| assistant `tool_calls[]` | `{ type:"function_call", call_id, name, arguments }` |
| `role:"tool"` | `{ type:"function_call_output", call_id, output }` |
| `tools[].function` | flat `{ type:"function", name, description, parameters }` |
| `reasoning.effort` | `reasoning.effort` |
| `temperature` | omitted for Responses |
| `max_tokens` | `max_output_tokens` |
| `stream_options.include_usage` | not sent |
| `store` | `false` always |
| `include` | `reasoning.encrypted_content` only when an effort is sent |

Why `store:false`: MyAgent is local-first. Responses must not be retained by the
provider for 30 days. With stateless mode the provider returns reasoning items
with opaque `encrypted_content`; those items are replayed in the next tool turn.

### Reasoning replay

When a Responses turn produces tool calls, `response.completed.response.output`
contains reasoning, assistant-message and function-call items. The adapter keeps
that array on the assistant history row as `responses_items`. On the next request
it sanitizes and replays those items, then fills any assistant message or
function call that the provider omitted from the completed output using the
Chat-shaped history. This preserves the model's reasoning across the tool loop,
avoids duplicate assistant messages, and never sends a `function_call_output`
without its matching `function_call`.

Sanitization keeps only replayable fields:

- reasoning: `type`, `id`, `encrypted_content`, optional `summary`;
- message: `type`, `id`, `role:"assistant"`, `content[]` of `output_text` /
  `refusal`, optional `phase`;
- function call: `type`, `id`, `call_id`, `name`, `arguments`.

Unknown output item types are dropped. Items without encrypted reasoning content
are dropped, because they cannot be replayed in stateless mode.

## 5. Stream mapping

`POST /responses` with `stream:true` is parsed by the existing SSE parser; the
event name lives in the JSON `type` field.

| Responses event | Internal effect |
| --- | --- |
| `response.output_text.delta` | `StreamEvent::Delta` |
| `response.refusal.delta` | `StreamEvent::Delta` |
| `response.reasoning_summary_text.delta` | `StreamEvent::Reasoning` |
| `response.reasoning_text.delta` | `StreamEvent::Reasoning` |
| `response.output_item.added` (`function_call`) | start a call slot keyed by item id |
| `response.function_call_arguments.delta` | append arguments |
| `response.function_call_arguments.done` | set final arguments |
| `response.output_item.done` (`function_call`) | upsert id, name, arguments |
| `response.output_item.done` (`message`) | text fallback only when no deltas arrived |
| `response.completed` / `response.incomplete` | usage, finish reason, raw output items, done |
| `response.failed` | `AppError::Upstream` with the provider message |
| `error` | `AppError::Upstream` with the provider message |

The authoritative tool calls come from `response.completed.response.output`.
Deltas are used only to keep the live slot up to date; a call seen only in
deltas is kept if the completed output is partial. `call_id` becomes the
internal call id, so the existing `role:"tool"` / `tool_call_id` round trip keeps
working.

Finish reasons:

- `completed` → `stop`
- `incomplete` + `max_output_tokens` → `length`
- any other incomplete reason → that reason
- `failed` / `cancelled`, or an unknown status → provider error / no finish

Usage is read from `response.usage` through the existing `normalize_usage`, which
already understands `input_tokens` / `output_tokens`.

## 6. Non-stream calls

`complete_text`, `summarize` and `suggest_title` check the per-model marker
first, then try Chat Completions and retry Responses once on the marker. The
Responses text extractor walks `output[]` → `message` → `content[]` →
`output_text` / `refusal`. A non-stream body with `status:"failed"` or a
top-level `error` becomes a typed upstream error, and an empty body is an error.

- summary keeps `max_output_tokens: 500`;
- title keeps `max_output_tokens: 2048`;
- temperature is omitted for Responses;
- the existing `clean_title` and 2000-char summary cap stay unchanged.

## 7. Failure matrix

| Failure | Behaviour |
| --- | --- |
| Chat returns the marker | Mark key, retry once against `/responses` |
| Responses also returns 400 | Surface the provider message; do not loop |
| 401 / 403 | Surface as today; no mode change |
| 429 / 5xx | Existing backoff inside `post_with_retry` |
| Network drop before bytes | Existing retry path |
| Network drop mid-stream | Surface; no duplicate request |
| `response.failed` | Surface its `error.message` |
| Non-stream `status:"failed"` / top-level `error` | Surface the provider message |
| Empty stream or empty non-stream text | `empty response from provider` |
| Tool arguments split across deltas | Accumulate; completed output wins |
| Completed output is partial | Keep calls seen only in deltas |
| Output item has no `call_id` | Fall back to item `id`, then `call-{index}` |
| Reasoning item has no encrypted content | Drop it from replay |
| Cancelled | `Ok(None)` / `Cancelled`, no retry |
| Gateway omits `response.completed.output` | Keep accumulated calls |
| Marker arrives after any visible event | Surface the error; never replay the turn |
| Stream or tool arguments exceed caps | Stop with a typed upstream error; never execute a partial call |

## 8. Tests

Unit:

- marker detection for the exact AgentRouter message and near misses;
- cache key isolates base URLs and models;
- `input` converts text, image parts, assistant tool calls and tool results;
- raw `responses_items` replay keeps reasoning and calls, and fills a missing
  assistant message or function call from the Chat-shaped history;
- sanitizer drops unknown items and reasoning without encrypted content;
- tool specs flatten from `{function:{…}}` to `{name,…}`;
- text extractor reads multiple message parts and refusals;
- stream state accumulates split argument deltas;
- completed output overrides incomplete deltas;
- completed output that omits a function call still replays the call seen in deltas;
- `response.failed` and top-level `error` become upstream errors;
- finish mapping for completed, max-output and other incomplete reasons;
- unknown response status does not claim a normal stop.

Manual:

- AgentRouter with `gpt-5.6-sol`: plain chat, one tool call, a title and a
  summary;
- AgentRouter with `gpt-6-astra`: same;
- OpenRouter/DeepSeek still use Chat Completions and show no extra request;
- cancel mid-stream leaves no second request;
- a 401 still shows the key error, not a mode error.

## 10. Accepted risks

- **One wasted 400 per model per launch.** Accepted; no schema or persisted
  provider quirks.
- **Gateway drift.** A gateway may implement a subset of Responses. The adapter
  follows OpenAI's current shape and surfaces the provider's error rather than
  guessing.
- **Temperature is ignored on Responses.** Reasoning models reject or ignore it;
  omitting it is safer than a second validation error.
- **Encrypted reasoning is opaque.** It is stored only in the conversation
  history sent back to the same provider; it is never parsed or shown.
- **No live integration test in CI.** The AgentRouter key is user-owned. CI
  covers the pure adapter and the existing provider tests; manual acceptance uses
  the user's key.
- **Bounded provider input.** A hostile gateway can still send a very large but
  under-cap stream. Caps stop runaway text, reasoning, item count, SSE events and
  tool arguments; they do not add a token budget.
- **GPT-6 Astra / 6.1 Sol reject `none` effort.** The adapter omits `none`, which
  lets the model use its default. A user who explicitly picks an unsupported
  effort still gets the provider's 400.
