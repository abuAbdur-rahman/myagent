# Plan: 0.8.0 hardening, eval and optional local navigator

Status: active. Target release: 0.8.0. Baseline: 0.7.1 (`10deee3`).
Parent plan: `v0.7.0-mcp-computer-use.md` (shipped with 0.7.0).
1.0.0 handoff: `docs/releases/v1.0.0.md` (integration, clean-machine eval and
security review).

## Scope decision

0.7.0 shipped the MCP setup/safety foundation and the computer-use
observe/action server. It explicitly deferred the following to 0.8.0:

- Computer-use hardening and the scripted observe/action eval harness.
- Publisher-signature verification and yield-to-user pause detection.
- Protocol `server/discover` probing, `Mcp-Method` / `Mcp-Name` headers and
  `tools/list` `ttlMs` / `cacheScope` caching.
- A Rust-owned MCP state machine, Form/JSON tabs, a details page, a composer
  server chip, and error kinds with a next action.
- The optional local navigator experiment.

0.8.0 completes that list. It does not start a new protocol experiment and does
not add a new platform. 1.0.0 remains the integration, clean-machine eval and
security-review release.

## Baseline verified in code

- `src-tauri/src/mcp.rs` `McpState` holds `sessions`, `catalog` and `probes`.
  There is no per-server transition machine with `starting`, `busy` and
  `stopped` states.
- MCP settings live in `src/components/settings/SimplePages.tsx`. Advanced
  fields exist inside a `<details>` block, but there is no Form/JSON editor, no
  Tools/Logs/Config/About details page and no composer server chip.
- No code path sends `server/discover`, `Mcp-Method`, `Mcp-Name`, `ttlMs` or
  `cacheScope`.
- `computer_use_server.rs` sets per-monitor DPI awareness v2, but the
  multi-monitor/eval/orphan-cleanup work is not implemented.
- `AppPolicy.publisher` exists in `computer_use.rs`, but the UI writes `null`
  and the server does not verify a signature.
- No `jev` sidecar, local-navigator benchmark or navigator UI exists.

## Workstream A: MCP runtime state machine and error kinds

**Goal:** the UI renders Rust state and sends intents only.

- Add a per-server state enum: `disabled`, `starting`, `ready`, `busy`,
  `needs_auth`, `needs_review`, `failed`, `stopped`.
- Move probe, connect, reconnect, enable/disable and approval transitions into
  the manager. Keep one session per server key.
- Return typed error kinds, a human message and a next action. At minimum:
  `not_found`, `invalid_config`, `spawn_failed`, `handshake_timeout`,
  `auth_required`, `auth_expired`, `tool_review_required`, `connection_failed`,
  `protocol_unsupported`.
- Keep the existing `McpProbe` shape for compatibility until the UI migrates.
- Tests: transition table, duplicate connect, disconnect while starting, failed
  start, auth required, review required, and restart after failure.

**Files:** `src-tauri/src/mcp.rs`, `src/lib/api.ts`, MCP settings tests.

## Workstream B: MCP protocol refresh

**Goal:** negotiate the current protocol without dropping legacy servers.

- Probe `server/discover` first, then fall back to the `initialize` handshake.
- Show the negotiated revision in server details.
- Send `Mcp-Method` and `Mcp-Name` on Streamable HTTP requests.
- Cache `tools/list` using `ttlMs` and `cacheScope`; revalidate on
  `notifications/tools/list_changed`.
- Keep Streamable HTTP and legacy `sse`. Do not add a new HTTP+SSE
  implementation or remove `sse` while target servers still need it.
- Do not build Roots, Sampling or Logging.
- Tests: discover success, discover fallback, legacy initialize, header
  presence, cache hit/expiry, and `list_changed` revalidation.

**Files:** `src-tauri/src/mcp.rs`, `src-tauri/Cargo.toml` if `rmcp` needs a
version bump, protocol tests.

## Workstream C: MCP settings UX

**Goal:** the user can diagnose and operate a server without reading logs first.

- Server details page with Tools, Logs, Config and About.
- Add/edit dialog with Form and JSON tabs; validate both through the same
  config parser.
- Stepped Test connection: config, spawn/connect, handshake, tools, done.
  Every failed step shows the error kind and the next action.
- In-chat tool-call and approval cards.
- Composer server chip showing the active project/global servers and their
  state.
- Progressive disclosure: simple fields first; advanced section for protocol
  override, catalogue/execution timeouts, headers, env and OAuth metadata URL.
- Default protocol to Auto.
- Tests: form/JSON round-trip, invalid JSON, test-step failure, details tabs,
  chip state, and approval card.

**Files:** `src/components/settings/SimplePages.tsx`, `src/components/Composer.tsx`,
`src/components/MessageList.tsx` or `TurnCards.tsx`, `src/lib/mcp-draft.ts`,
`src/lib/api.ts`, component tests.

## Workstream D: computer-use hardening

**Goal:** the shipped tools survive real Windows apps on a clean machine.

- Lazy Chromium/Electron UIA trees; do not walk the whole browser tree before
  falling back to pixels.
- Multi-monitor and DPI coordinate checks; keep physical pixels and DPI
  awareness v2.
- Elevated-window and secure-desktop errors: refuse with a typed error, never
  send input.
- Stale snapshot recovery and orphan-process cleanup.
- Audit viewer, dry-run and action-budget polish.
- Installer checks for the bundled server binary and any sidecar.
- Tests: tree cap, stale snapshot, multi-monitor coordinates, secure-desktop
  refusal, orphan cleanup and dry-run.

**Files:** `src-tauri/src/computer_use.rs`,
`src-tauri/src/computer_use_server.rs`, `src/components/settings/SimplePages.tsx`,
computer-use tests.

## Workstream E: computer-use trust

**Goal:** an approved app cannot be silently swapped and the user can take over.

- Populate `AppPolicy.publisher` from the executable signature.
- Verify publisher on approval and before use; mismatch warns or blocks.
- Yield-to-user detection: pause the run when the user moves the mouse or types
  outside the agent's intended action.
- Keep hard denies, tiers, kill switch and audit authoritative.
- Tests: publisher match, mismatch, unsigned binary, user takeover pause and
  resume.

**Files:** `src-tauri/src/computer_use.rs`,
`src-tauri/src/computer_use_server.rs`, settings page, tests.

## Workstream F: scripted eval harness

**Goal:** a repeatable pass/fail signal before action tools are exposed.

- About twenty Windows tasks: Notepad, Explorer, Settings, a Chromium form, a
  WinUI dialog, a long list and a modal.
- Record success, steps, tokens, wrong clicks and time.
- Run on a clean Windows machine.
- Gate action tools on the observe eval passing; keep the safety gates intact.
- Store the harness and fixtures in the repo; do not require a cloud account
  beyond the model call.

**Files:** `src-tauri/tests/` or a dedicated eval crate/script,
`docs/releases/v0.8.0.md`, CI or a documented manual command.

## Workstream G: optional local navigator (J14)

**Goal:** ship tier 2 only if the benchmark gates pass.

- `jev.exe` + jevos-v5 OpenVINO INT8; yes/no verifier, not a chooser.
- Ask one question per top candidate. Act only when calibrated best is
  `>= 0.80` and the runner-up is `< 0.50`; otherwise escalate to tier 3.
- Spawn as a sidecar with `CREATE_NO_WINDOW`, Job Object, random localhost port
  and API key, idle stop and below-normal priority.
- Shadow mode for 1-2 weeks; off by default; tiers 1 and 3 must work without it.
- Gates: p50 `<= 3 s` plugged in / `<= 5 s` on battery, `>= 90%` top-1 on
  calibrated `p >= 0.80`, `>= 60%` of steps finished without the cloud.
- Settings: toggle, status pill, disk size, delete model, run benchmark and
  audit columns (step, candidates, probabilities, tier, ms).
- If the gates fail, ship 0.8.0 without tier 2 and record the result.

**Files:** new sidecar integration, `src-tauri/src/computer_use.rs`,
computer-use settings, benchmark tests.

## Acceptance gates

- A standard `mcpServers` file imports, runs and exports without losing secrets
  or app-only policy.
- A failed server shows a human error, the failing step and a next action.
- A changed tool definition moves the server to `needs_review`.
- Closing the app leaves no child process behind.
- `server/discover` falls back to `initialize`; legacy `sse` still works.
- `Mcp-Method` / `Mcp-Name` are present on Streamable HTTP requests.
- `tools/list` honours `ttlMs` / `cacheScope` and revalidates on `list_changed`.
- The computer-use observe eval passes before action tools are exposed.
- Action tools refuse hard-denied apps and secure-desktop input.
- The kill switch interrupts an in-flight action.
- Publisher mismatch cannot silently approve or run an app.
- User takeover pauses a run.
- The local navigator is either absent or passes every benchmark gate.
- The full local gate is green.

## Out of scope

- No new MCP protocol experiment beyond discovery, headers and cache.
- No Roots, Sampling or Logging.
- No macOS/Linux/mobile branches.
- No elevated agent, secure-desktop input, raw shell in the computer-use
  server, remote steering or local vision model.
- No new v1 feature list; 1.0.0 is integration and security review, not a new
  product surface.

## Verified protocol support (2026-10-30)

- `rmcp` 3.7.0 `ClientLifecycleMode::Auto` already probes `server/discover` and
  falls back to `initialize`; the current client uses that mode.
- `rmcp` 3.7.0 sends `Mcp-Method` and `Mcp-Name` on Streamable HTTP requests.
- `ListToolsResult` exposes `ttlMs` and `cacheScope`; MyAgent now stores both on
  the session and probe and uses `ttlMs` for the tools refresh decision.
- No HTTP-layer reimplementation is needed for discovery or headers.
