# v0.3.0 J12b — MCP (every tool through permission engine)

Slice 4, after J12a. Only after D4/D5 proven (already shipped).

## Done
MCP tool cannot run without passing permissions.

## Locked decisions
1. Single Rust MCP manager, tools namespaced `<server>_<tool>` (opencode `tool/mcp.ts:16-17`). Reason: one lifecycle owner, collision-free actions for permission rules.
2. Config minimal: `{name, cmd|url, allowTools[]?, timeoutMs?}` — project-scoped, stored beside connections (vault for headers/secrets, never in chat rows). Reason: opencode full shape deferred; allowlist covers least-privilege now.
3. Permission default Ask for new MCP tools; rules addressable per `server_tool` action + `server:*` wildcard (`permission.ts:87-97` last-match-wins analog already in `permissions.rs:64`). Resource granularity action-only v1 (`resources=["*"]`, opencode `mcp.ts:51-63`). Reason: matches existing engine, zero new semantics.
4. `inputSchema` JSON passed straight to OpenAI function spec, args validated server-side only (opencode `mcp.ts:47-48`, `Tool.make` unknown-in/out). Reason: no conversion bugs.
5. Per-call timeout 60s default → cancel + `ToolFailure{code:"timeout"}` + server restart after 3 consecutive timeouts ([SPEC] gap: opencode has no timeout layer). Reason: hung stdio must not hang turns.
6. Discovery at startup; block first send on settle (`flush`, opencode `mcp.ts:144`); 100ms-debounce refresh on `tools/list_changed` preserving order (`mcp.ts:131-143`). Reason: no ghost tools, no flapping.
7. Filtering ≠ authorization: hidden-from-model still asserts at leaf (`AGENTS.md:52-54` analog = keep `RealTools::run check()` at `llm.rs:1261` as sole gate for MCP too). Reason: defense in depth.
8. Failure strings: server-down → `MCP_UNAVAILABLE:{server}`; `isError` → joined text as tool error (`mcp.ts:72-76`); timeout → `MCP_TIMEOUT:{server_tool}`. Reason: model-actionable, log-friendly.
9. Resources (`list/read`) skipped v1 — tools-only. Reason: scope control; revisit post-v0.3.0.
10. Transport v1: stdio + SSE; streamableHTTP follows if trivial, else deferred with explicit `UNSUPPORTED_TRANSPORT`. Reason: stdio covers local servers, SSE covers remote.

## Steps
1. Manager (`src-tauri/src/mcp.rs` + state in `state.rs`): spawn stdio / connect SSE, `initialize` + `tools/list`, catalog `{server, tool, schema}`, `tools/list_changed` resubscribe with debounce.
2. Tool specs: MCP catalog → same `tool_specs()` shape as native tools; `summarize_call` → `{server_tool}` short; `execute` arm routes `mcp.callTool` with session/request id threading.
3. Permission: `approval_resources` (`llm.rs:809`) returns `[server_tool]`; check stays in `RealTools::run` (`llm.rs:1261`), fail-closed Ask. `allow_always_from` refusal of `*` already correct.
4. Audit: each MCP call logs via `log_audit` (`tools.rs:790`) under J8 writer rules.
5. UI: servers list + enable/disable + per-tool Always in Settings (extends search-provider section pattern); approval card shows `server_tool` + summarized args (existing `ApprovalCard`, no new component).
6. Failure mapping per decision 8; timeout via `tokio::time::timeout`, restart counter per server.
